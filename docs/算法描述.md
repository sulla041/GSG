# 算法描述

## V3.02 纯净动力学机制与解耦基底（2026-10-29）

V3.02 在 V3 集合内部动力学基础上，确立了“赋予模型消息传递选择权”与“尺度不变纯净物理累加”两大核心原则：

### 1. 点对运算基底扩展（解耦源状态与目标状态）
原版 V3 点对运算完全基于差分、哈达玛积等相对项，剥夺了模型将特征退化为经典 GNN 纯源节点消息传递的自由度，也削弱了目标节点以自身为参照系的自省与门控能力。V3.02 将有序点对 $(s_j, s_i)$ 的交互基底显式扩展为六元基：
$$Z_{ji} = \big[ s_j,\; s_i,\; s_j - s_i,\; s_j \odot s_i,\; W_{\text{src}} s_j - W_{\text{dst}} s_i,\; \|s_j - s_i\|_2 \big]$$
总特征宽度为 $5d_s + 1$。
- **演化阶段（offre）**：输入由纯几何基底与先验关系拼接构成：$\text{features}_{ji} = [Z_{ji},\; re_{ji}]$；
- **读出阶段（rout）**：剥离外部先验关系，仅凭同构的纯几何基底生成下游预测：$r_{\text{out}}(j, i) = \text{rout}(Z_{ji})$。
由此，`offre` 严格比 `rout` 仅多一个外部先验关系 $re_{ji}$ 输入，彻底对齐演化与读出的几何度量。

### 2. 尺度不变纯净累加（移除 $1/N$ 归一化与外生步长）
- **移除总节点数归一化**：拓扑跳数计算本质为离散步数累加。原版 $\frac{1}{N_{\text{valid}}} \sum_j$ 操作导致单个邻居位移随全图规模 $N$ 剧烈衰减，且受海量 $r_{\text{null}}$ 背景对稀释。V3.02 彻底移除除以 $N$，改为纯粹的 `sum` 累加：
  $$\text{field}_i = \sum_{j} \Big( \text{gate}_{ji} \cdot \text{offset}_{ji} \Big)$$
- **移除冗余固定步长**：取消外生常数步长 $\eta=0.05$，将状态演化还原为纯净的物理势能累加：
  $$s_i^{(t+1)} = s_i^{(t)} + \text{field}_i + \text{noise}$$
在 CLRS 8 层真实图实验中，该纯净机制使正跳数 MAPE 从 $31.79\%$ 骤降至 $13.07\%$，全可达 MAE 降至 $0.2360$，舍入跳数准确率提升至 $88.83\%$，且动力学场在多层演化中展现出自发能量稳态（field RMS 稳定于 $0.4188 \sim 0.5548$）。

## 稠密直接关系下游任务（2026-10-29）

电路关系下游任务固定为对所有语义成立的直接 arc 进行监督：全部合法 `combinational_cell_arc`、全部合法顺序 `clock_to_q/setup/hold/recovery/removal` arc，以及 physical-level 中全部可提取的 driver-to-sink `net_arc`。这些 relation 的分母分别由 Liberty、mapped netlist、SDC 和 SPEF 共同确定；任务必须报告 `labeled/eligible`，目标是定义分母内 `100%` 覆盖。rise/fall 或 timing-sense 不适用时用通道 mask 表示，不把 `N/A` 补为零。

稠密并不等于为所有 `N^2` 节点对构造伪延迟标签。`r_null` 保留为输入离散关系，不进入连续 delay loss；无直接且可计算物理语义的节点对也不成为回归样本。历史 Launch-Capture endpoint pair/path delay 因为天然稀疏，不再作为主关系下游任务；它可保留为图级 QoR 或受限评估，而非训练集的关系覆盖指标。

physical relation 另外分为两个任务视图。`G_route` 只含 route geometry、邻近几何和 RC corner，预测 `route_segment` 电阻、node-to-ground 电容与 coupling candidate 电容；`G_rc` 输入已提取 RC 网络，预测全部 eligible driver-to-sink net arc delay。前者不得输入 SPEF 数值，后者可以输入 R/C，因为二者目标不同。无向 resistor/coupling 以成对有向 relation 表示并共享一个 loss id，防止重复计数。

ORFS 的 physical flow 要求 Yosys 同时支持 Tcl 与 `read_liberty -unit_delay`；本机 Yosys 0.31 不满足该接口，实际物理数据构造固定使用 `/data/yiyh/dac2027/envs/yosys_orfs/bin/yosys`（0.69）。OpenRCX SPEF 可能将同一 coupling capacitor 在两个 net section 镜像写出，数据导出按无向端点与数值去重，并保留 `raw_coupling_caps` 供 provenance 审计。

首个 Nangate45/GCD `physical_rc_complete` 样本验证了上述 R/C 关系标签闭环：SPEF 有 `1,813` resistor、`2,539` ground capacitor 和 `4,913` 个去重 coupling capacitor。该事实只确立 RC extraction 关系任务的标签来源；在 DEF/ODB 转为不含 SPEF 数值的 `G_route` 前，不能对 R/C 预测训练，也不能将 RC 工件完整误报为 dense net-delay 完整。

## DAC EDA 标签流水线边界（2026-10-28）

DAC 数据构造采用 `Verilog -> Yosys netlist/JSON -> graph G`，再根据标签层级生成 `G'`。Yosys/ABC 与 OpenSTA 产生的综合级结果单独标记为 `synthesis-level`；经过 OpenROAD placement/CTS/routing、OpenRCX SPEF 和 post-route OpenSTA 的结果才标记为 `physical-level`。两级结果不混合为同一标签。

截至 2026-10-28，Yosys 0.31、OpenSTA 2.2.0 和 OpenROAD CLI 均已在本机完成独立可执行 smoke。OpenSTA 的调用必须显式加载项目 GCC 13 运行库和 `v2ex_cuda` 环境中的 Tcl 8.6；OpenROAD 当前为 Bazel CLI-only 构建，不包含 GUI、GPU 或 Python 扩展。工具可用不等于完整数据流水线已验收，端到端闭环仍需单独记录输入、图导出、标签覆盖率和失败阶段。

图适配器必须保留 Verilog/netlist 名称到节点和关系的 provenance 映射，并区分 `r_null`、直接结构关系、方向和 padding。OpenSTA 的 delay/slack/path 标签只进入目标图 `G'`，不能反向成为输入图的拓扑或节点特征；缺失标签通过有效性 mask 表示，不补零为监督。

## V3 edge-only 消融（2026-10-28）

该消融测试 V3 的全节点对动力场是否受到 `r_null` 作用过宽的影响。输入关系仍有 `r_null/edge/self` 三类；动力学中只保留 `edge` 和 `self` 的 `pair_contribution`，`r_null` 的 offset/gate 不进入 `pairwise_field`。读出端不做这个限制，仍对所有有效节点对使用 `rout` 预测输出关系。该版本只改变动力学作用 mask，不改变交互函数、噪声、loss 或读出接口。

作用 mask 必须从原始关系类别生成，再传给关系编码后的动力学函数；不能使用 `enc_r(reij)` 的某个通道判断关系类别。初版长日志因这一接口错误与原 V3 完全一致，修正版已增加 `r_null contribution == 0` 的 CUDA 断言。

## GNN 对照结论（2026-10-28）

8 层关系 GNN 在 CLRS hop 任务上达到 loss=`0.124749`、MAPE=`23.9731%`、MAE=`0.389937`，优于相同 8 层预算的 V3（MAPE=`31.7850%`）和 V3.01-attn（MAPE=`31.5998%`）。这说明该任务的核心结构与“沿直接边逐层扩散”高度相关：GNN 的每层邻域传播与最短路径 hop 的生成过程形成一致归纳偏置。

该结果支持以下判断：attention-style 点对投影本身没有弥补 V3 全节点对交互的拓扑约束不足；对于跳数监督，显式 `edge/self` 传播比允许 `r_null` 参与的稠密全对动力场更有效。这个结论属于当前 CLRS train-only、单 seed、相同 1000-step 协议下的算法对照，不延伸为所有图任务的普遍结论。

## 独立关系 GNN 对照（2026-10-28）

GNN 对照用于区分“显式输入边上的多层传播”和 V3 的“全节点对潜在交互场”。每层关系条件消息函数读取源状态、目标状态和关系投影，只保留 `edge/self` pair，`r_null` 不参与传播；聚合后做节点残差更新，重复 8 层扩大图上的邻域感受野。终态再用 pair decoder 读出全有序节点对跳数。

该基线不是 V3 的架构修改：V3、V3.01-attn 和 `v3_gnn` 各自独立。GNN 不使用 V3 的自适应噪声、连续 pairwise field 或 gate；比较时保持 CLRS 数据、reachable Smooth L1、训练预算和 CUDA 环境一致。Transformer 也可以视为集合内部相互作用的一种，但 GNN 对照刻意保留输入图邻接约束，用来测量显式拓扑传播本身的能力。

## V3.01-attn 设计（2026-10-28）

V3.01-attn 是 V3 的独立交互基版本。`offre` 与 `rout` 使用同一套扩充后的点对运算，保证动力学作用和关系读出在交互语义上同步；`offre` 额外接收 `reij`，`rout` 只接收终态状态 `S`。新增运算为 `q_i=W_qs_i`、`k_j=W_ks_j`、`v_j=W_vs_j` 派生的 `q_i⊙k_j`、`q_i-k_j` 和 `v_j`，与原有 difference/product/directed/distance 并列输入 MLP。

这里的 attention 是集合内部的点对相互作用，不是 Transformer 替换：没有多头、LayerNorm、FFN、softmax attention 矩阵或独立 token 聚合；所有交互仍通过共享 `offre` 生成 `pair_offset`、`pair_gate`、`pair_contribution`，再汇总为 `pairwise_field`。

## V3 诊断口径（2026-10-28）

V3 不采用“消息传递”作为核心语义。对每个有序节点对 `(i,j)`，点对函数产生 `pair_offset_ij`，由 `pair_gate_ij` 调节后形成 `pair_contribution_ij`；所有有效节点对的贡献共同聚合为 `pairwise_field_i`，再更新节点状态。该机制用于建模直接边和 `r_null` 所代表的潜在节点联系，不等价于沿输入边逐层传递消息。

逐层关系稳定性通过在每个中间状态 `S_t` 上复用同一个 `rout` 读出测量：记录 `rout(S_t)` 的任务误差、相邻层输出变化、状态位移与输出变化的比值、与最终层输出的相关性、相邻速度方向余弦以及 pair distance 变化。若状态位移增大而 rout 敏感度下降、预测相关性升高，说明可能存在读出稳定的集体运动；pair distance 同时增长时，还需保留“扩张”成分的解释。

完整 T=8 轨迹结果显示，step 2 后 `state_delta_rms` 持续增大，`rout_state_sensitivity` 从 `0.5593` 降至 `0.0563`，与最终预测相关性升至 `0.9884/1.0000`，速度方向余弦升至 `0.9861`。因此当前更准确的表述是“动力学状态进入读出等价的共同运动区间”；`pairwise_field` 仍在驱动几何扩张，尚不能称为相互作用场稳态。

动力学诊断按每个演化步记录节点位移，而不是只看混入噪声的总 update：`node_displacement_mean/max` 是实际 `S_{t+1}-S_t`，`node_field_displacement_mean` 是 `eta*field` 的节点范数均值；field、interaction、noise RMS 继续保留。

交互输入的作用使用零化敏感性测量。对 `difference`、`product`、`directed`、`distance`、`reij` 各自置零，重新经过同一 `offre`，以 `field_delta_rms` 衡量完整场与零化场的差异；它包含 offset 和 gate 两条非线性路径，不是可加的 Shapley/因果分解。输入 RMS 只描述输入尺度，不能代替 field delta。`reij_field_delta_rms` 专门诊断关系编码对动力学场的影响。

`offre` 与 `rout` 的职责分开：`offre` 是跨时间共享的关系条件向量场，每一步生成并聚合节点位移，改变 `S`；其中 `offre.route` 只是生成 sigmoid gate 的内部子网络。`rout` 是终态关系读出头，只读取最终点集的点对特征输出 hop，不参与中间状态更新；hop loss 通过 `rout` 直接监督，并经最终状态反传到动力学。因而 `offre` 的块敏感性与 `rout` 的输出范围/读出误差应分别统计，不直接比较两个 RMS 后下结论。

探针结果的 `best_probe.steps` 保存上述逐层值，`best_probe.readout` 保存 `rout_output_rms/abs_mean/min/max`；这些诊断不改变前向、噪声、loss 或最佳 checkpoint 选择。

## V3 训练结果与主评估指标（2026-10-28）

context=none 的完整 1000-step 训练已完成，主实验继续采用直接点对运算。最佳已测完整训练 loss 在 step 900：
loss=0.183667、全可达 MAE=0.484194、舍入准确率=61.4337%；尚未通过 SETATTN 对照判断上下文的额外作用。

按用户最新意见，V3 日志与主评估使用正跳数 MAPE：
`MAPE_percent=100*mean(|prediction-hop|/hop)`，mask 为有效、可达且 hop>0 的 pair。
它按每个真实 hop 归一化误差，具有连续的相对误差含义；不需要先按预测值范围做 min-max。
0 跳单独报告 `zero_hop_mae`，并继续参与原 Smooth L1 和整体 MAE；sentinel/padding 排除。
没有正跳数 pair 时 MAPE 为 null，日志为 n/a；不添加 epsilon 或截断负预测/超过 100% 的误差。
逐 hop MAPE、pair 数、整体绝对误差和原舍入指标同时保留；同样绝对误差在短跳数上的相对惩罚更大，
因此分析远跳能力时还要看逐 hop MAE。最低权重仍按完整训练 Smooth L1 选择，网络和监督目标保持原样。

按原结果逐 hop 数量及 MAE 加权汇总，最佳权重的正跳数 MAPE=30.06208%，共 232,948 个 pair；
0 跳有 16,000 个 pair，MAE=0.265402。统计口径为逐 pair 等权，不是逐 hop 桶等权。
test 阶段已通过 CUDA MAPE 单测及相同随机序列的两步训练 smoke，原始 loss 完全对应，随后提升到 code/v3。

## V3 独立首版实现（2026-10-28，CUDA smoke 阶段）

用户已授权依据草案与后续澄清实现独立 V3。实现先在 `test/v3/` 通过 CUDA 接口、真实 CLRS 两步训练和
最佳权重保护测试，随后原样提升到 `code/v3/`；入口为 `script/train_v3_hops.py`。V2-EX 原实现保留。

- enc_x/enc_r 用两层 GELU MLP 映射至相同状态宽度，默认 d_s=32、hidden=64；首版沿用未归一化坐标残差。
- 点对运算为 `s_j-s_i`、`h_j*h_i`、`W_src h_j-W_dst h_i`、`||s_j-s_i||_2`，按通道拼接。默认 `context=none` 时 h=s；`context=setattn` 使用独立上下文分支，位置差始终取原坐标。两配置均通过接口 smoke，尚未比较任务效果。
- offre 接收点对运算与 enc_r(r) 的拼接，MLP 生成位移，另一个 MLP 生成 sigmoid gate；按有效源节点数平均 gate*位移。整个 offre 跨演化步共享，显式 eta 默认 0.05；这些是登记的首版实验配置，聚合优劣仍待诊断。
- 保留当前 V2-EX 噪声公式：节点间均方距离的高斯聚拢度、noise_max=0.01、temperature=1、单调尺度包络和 1e-6 退出阈值。训练及评估均注入噪声；评估使用独立随机生成器和固定 seed，避免改变训练 RNG。
- 终态 rout 通过独立点对运算和 MLP 输出关系向量，hop 配置输出一个标量；off 通过该读出点对特征输出节点位移，聚合后构造 s+offset，再接节点投影。演化与读出参数分开；off/rout 复用读出运算投影，但各自的输出 MLP 独立。hop 任务只执行 rout，独立 off/head 参数不参与该任务的梯度。
- CLRS 原 artifact 不变：在 batch 适配时将有效对角单独编码为 self，得到 1 种节点与 r_null/edge/self 三种可数关系。输入关系类别与输出 hop/sentinel 保持分离；这一输入 schema 与旧两关系 V2-EX 对照不同，比较算法效果时需要控制该差异。
- loss 沿用可达 pair 的 Smooth L1(beta=1)，保留自身 0 跳；仅读取 train。记录 batch/full-train loss 和 accuracy、逐 hop 数量/MAE/accuracy/预测均值、预测分布；按最低已评估完整训练 loss 保存 best_checkpoint，最终权重单独保存。两者包含 AdamW 和 Python/PyTorch/CUDA RNG 状态；当前训练入口尚未提供 resume 参数。
- 最佳权重的前八图探针记录每步 field/interaction/update/noise/coordinate/centered-coordinate RMS、gate 均值/饱和比例、消息抵消系数及噪声退出比例。该探针是小样本诊断，完整训练指标单独标记。

当前验证覆盖共享参数、非零有限梯度、sentinel/padding 零梯度、非零噪声、同步排列等变、变长图与全 padding、
padding 值扰动及新增无效节点隔离、读出只依赖终态、评估 RNG 隔离和最佳权重保护。该阶段确认实现与训练闭环，
本条记录的是首版 smoke 阶段，后续完整训练结果与评估口径见上方最新记录；泛化和相对 V2-EX 的优势仍需另行实验。全部新增 Python 文件少于 150 行，运行依赖仅为 PyTorch 和标准库。

## V3 设计思考起点（2026-10-28，按用户澄清）

设计输入为用户维护的 `v3.txt`，保持只读。本节保留实现前的已确认原则与数据流推演；随后授权的实现与实验配置见上方独立首版记录。

已确认原则：

- G=(X,R) 经关系条件化的点集演化得到 S，再仅根据 S 读出 G'。同维度编码是共同计算的基础，关系参与 offset 并累积改变节点状态才是内化与对齐的机制。
- offre 跨演化步共享，因为各步属于同一动力系统。offre、off、rout 三种用途之间是否共享参数是另一项实现问题，尚未固定。
- 保留用户指定的 V2 自适应噪声机制；自关系可设置为输入关系种类之一。G 中无直接边的输入关系与 G' 中不可达的目标关系属于不同层次。
- 按任务训练对应读出及其上游编码、演化。关系任务通过 rout 监督；独立 off 节点读出分支是否启用取决于任务。
- H_i、padding 的处理需实验诊断；聚合形式需依据消息贡献与信息保留诊断确定。稳定性可从坐标、交互模式、读出等角度界定，暂不强制唯一标准。
- V3 是通用图算法设计，节点/关系种类及其是否离散可数由具体输入 schema 登记，不把当前 CLRS 的种类数量固化到通用算子。

对既有公式的数据流推演：

1. 以 z_ji^t 记草案 a(s_j,s_i)、b(s_j,s_i)、c(s_j,s_i) 等运算的集合，仅为记号，不预先指定拼接或混合方式。
2. m_ji^t=offre_theta(z_ji^t,re_ji)，d_i^t=Agg_j(m_ji^t)。状态按草案残差规则与已确认自适应噪声演化。
3. 参数 theta 跨步保持相同，而 z_ji^t 随状态变化，因此相互作用模式可以随演化改变。
4. 某一输入关系改变节点 j 的状态后，下一步包含 j 的点对运算随之变化，其他节点据此得到不同偏移；这提供关系在状态中组合的计算路径。每步 dense 全局交互，内部步数不直接等于图跳数；路径存在并不自动保证关系组合信息被聚合和读出保留。
5. 最终 rout 读取终态点对特征；节点读出通过 off 聚合后与终态残差组合。共享的是点集所承载的结构信息，任务决定需要读出的属性。

下一步设计问题围绕三段接口展开：点对运算提供哪些信息；offre 如何使关系条件改变作用方式；Agg 如何把多源作用转为保留结构差异的单点更新。诊断应区分几何状态、相互作用模式和读出的演化，以此选择聚合与 H_i 的实现。上述是分析顺序，不构成添加新分支、损失、归一化或退火机制的授权。

## 分层 N² 建模探索（待审核，不进入当前主线）

当前 V1-C 的 `SETATTN`、`PAIRATTN` 和 `EvolutionLayer` 都会产生显式 pair/state 张量；只替换单个 QK kernel
不能消除完整 dense `N^2` 的显存开销。为覆盖 2048 以上的大图，保留现有 V1-C/global PAIRATTN 语义的候选方向是：

```text
G -> topology-only clusters -> local V1-C/PAIRATTN
  -> cluster token pooling -> cluster-level global context
  -> local context injection -> sparse relation PAIRATTN readout
```

建议的两级结构为：每个 cluster 内使用局部节点/关系上下文，cluster token 再进行全局 attention；同 cluster 的
`CELL_ARC` 由局部 pair readout 预测，跨 cluster 的 `CELL_ARC` 使用两个端点 embedding 和两个 cluster token
进行有序 pair readout。`NET_ARC` 仍只提供拓扑，不进入 delay loss。目标粒度仍是有效 relation，不改成节点 delay。

候选复杂度从 `O(N^2)` 转为 `O(sum(cluster_size^2) + K^2 + E_target)`；其中 cluster size 先考察 64/128，
`E_target` 是有效 `CELL_ARC` 数量。对更大图还需要递归 super-cluster，不能仅依赖一次 cluster-level dense attention。

数据契约必须保存 `cluster_id`、cluster members 的原节点顺序、cluster graph edge、跨 cluster edge 和反向映射；
所有 cluster 必须由图结构、节点类型和合法输入特征生成。外部已有 `labels_ppa_cluster_v2` 使用
`logic_cone_bfs_max64_v1`，但只覆盖部分设计且包含 `y_power` cluster target，因此只能作为分区实现参考，不能直接作为输入。

该方向当前只写入设计探索，不修改 `code/v1_c`，不改变正在运行的 `max_nodes=2048` 实验，也不产生正式性能结论。

## 下游任务与输入图视图

当前系统支持的是“同一物理数据的任务特定图视图”，不是要求所有任务共享同一个节点集合：

- **连续合成图：** 输入为连续节点和连续有向全关系；支持节点/关系重构，以及 `factorized` 和
  `two_hop` 生成的节点二分类、关系二分类。
- **分子图：** ZINC 使用 21 类节点、4 类稠密关系，QM9 使用 5 类节点、4 类稠密关系；支持
  节点类型和真实键/显式 `r_null` 的重构。
- **Cora masked graph：** 输入节点为 1,433 维特征、关系为 `r_null/observed citation`；支持
  7 类节点 subject 分类和隐藏边/匹配非边查询。
- **GSG SKY130 cell/net 图：** 支持节点 area、四类 instance power、timing observations/arrival/slew，
  设计 area/total power/WNS/TNS，及 `cell_to_net`、`timing_arc` 二分类关系；PPA multi-task
  还支持 4 类关系类别和 `delay/slack/critical` 连续 timing 标签。
- **DAC mapped-v2 图：** 支持 mapped-cell area 和四类 mapped-cell power，以及由节点物理求和得到的
  设计级 area/power。
- **DAC pin timing-v1 图：** 支持 `CELL_ARC` 的 rise/fall/worst propagation delay；`NET_ARC`
  目前只作为拓扑，不提供 delay 监督。

其中 GSG cell/net、DAC mapped-v2 和 DAC pin timing-v1 是三个不同的电路图视图。节点类型、关系
类型和 `r_null` 语义必须在每个任务 manifest 中单独声明；没有端点对齐的标签不得进入监督。
DAC 已接入 V1-C 单任务训练入口：mapped area、四个 mapped power、pin rise/fall/worst delay
分别使用独立模型和 checkpoint；graph area/total power只作为节点预测聚合评估。

旧 raw-scale DAC predictor test 结果保存在 `runs/dac2027_area_full_max1024/`、
`runs/dac2027_power_*_full/` 和 `runs/dac2027_timing_{rise,fall,worst}_full/`；八个历史任务均有最终
`test.json`，但不能代表当前冻结 log-space 版本。当前冻结结果输出到 max2048 目录；新结果应优先读取
`runs/dac2027_max2048_release.json`，旧 raw-scale/1024 目录仅作历史对照。

相对误差评估按单个 prediction 与对应 true label 计算，不进行设计级先验平均：
`relative_error=abs(prediction-true)/abs(true)`。每个任务的逐预测结果写入 `relative_errors.jsonl`；真实值为零时只保留
绝对误差并将 relative error 设为 `null`，以避免零分母产生伪指标。

## DAC predictor 当前输入充分性边界

现有 DAC 结果应解释为固定输入 schema 下的 baseline。mapped-v2 当前输入包含节点类型/family、drive strength、
sequential/reset/set 属性、pin 数量和 `drive_to_net/net_to_load` 拓扑，但没有 numeric activity/toggle、频率、
input slew 或 load/capacitance。pin timing-v1 当前节点包含 pin capacitance、方向、cell family 和 drive strength，
但 `CELL_ARC` 边没有 arc-specific slew、load 或 transition 条件。

因此，switching power 的高相对误差首先是输入信息不足问题；delay 虽然目标粒度正确地保持为 relation-level `CELL_ARC`，
但缺少边条件会限制预测。改进实验必须先完成字段来源审计、schema/tensor/mask 测试，再按单任务重新训练；不得把新增字段
默认值或标签反推值当作真实输入。

## 下一版数据集需求

- pin timing：每条 CELL_ARC 的有序 source/target pin、arc type、rise/fall 条件、input slew、output load/capacitance、

  才能与当前 baseline 正确比较。

## DAC-EDA 下游任务边界

`dac2027` 的 E-DAC 主任务不是泛化的“所有电路任务”，而是以下八个独立单模型目标和两个聚合评估：

1. mapped-cell Liberty area；
2. mapped-cell `internal` power；
3. mapped-cell `switching` power；
4. mapped-cell `leakage` power；
5. mapped-cell `total` power；
6. pin-level `CELL_ARC` rise propagation delay；
7. pin-level `CELL_ARC` fall propagation delay；
8. pin-level `CELL_ARC` worst propagation delay。

聚合评估为 graph area（由 area 节点预测求和）和 graph total power（由 total power 节点预测求和）。

mapped-cell area、四类 power 和三个 delay 通道分别训练；graph area 与 graph total power 分别由对应
节点预测求和得到，只用于评估，不进入其他任务的训练 loss。

`NET_ARC` 当前只表示理想互连拓扑，不进入 delay loss。节点/边恢复指标是辅助表示证据，不能
替代上述八个主任务。DAC Agent Phase 2 另外定义四个真实 EDA 优化任务：T1 timing closure、
T2 area compression、T3 power compression、T4 multi-objective PPA；它们需要真实 EDA flow
和等价检查，不能等同为静态 PPA 回归任务。

统一 pair 数据位于 `dataset/paired_graphs/`，当前 manifest 有 `5,772` 个完整 pair：
open_verilog `5,021`、CircuitNet `627`、EPFL `26`、ITC99 `76`、OpenLane-local `1`、
TimingPredict `21`。这些数量是来源审计后的正式统计，不包含 CircuitNet 的 264 个 partial-label
额外目录。

当前实验准备边界：V1-C 的点集编码、关系演化、自适应噪声和独立解码结构保持既有规格；PPA
监督接口已经完成短 smoke；DAC 单任务实现通过字段级 mask、训练统计标准化和 batch padding 处理缺失值。
当前正式 predictor 使用冻结 source-family split、CUDA 和冻结 `max_nodes=2048`，每个任务独立报告结果，
不能把一个任务的结果外推到其他任务。

首个真实 pair audit smoke 显示节点类型为 `cell/net`，关系标签至少包含 `cell_to_net`，部分
来源包含 `timing_arc`；area 覆盖率是来源相关的，power/timing 覆盖率可能为零。该结果说明训练
前必须按标签字段和 `has_*` 掩码分层统计，不能把所有 5,772 个 pair 当成同质 PPA 监督样本。

full audit 结果进一步确认：TimingPredict 的 21 个 pair 均有 power/timing 标签；open_verilog
为混合覆盖；CircuitNet 627、EPFL 26、ITC99 76 和 OpenLane-local 1 个 pair 当前没有非零
power/timing fine-node coverage。当前最稳妥的实验准备是先做结构/area 子任务或按来源建立独立
监督子集；power/timing 任务必须只使用对应 `has_*` 字段有效的 pair。

## EDA downstream 任务边界（2026-10-23）

EDA 主目标不是恢复完整图 `G'`，而是验证编码点集 `S_e` 是否支持实际 PPA 下游任务。当前优先级为：

1. 节点任务：对每个 cell/node 预测 area、power 或 timing 连续标签，只在对应 `has_*` 有效节点上计算损失和指标。
2. 关系任务：对有序 timing arc 预测 delay、slack、criticality；关系端点必须先映射到输入图节点，未映射关系不能进入监督。
3. 设计任务：作为补充，对整张设计预测 total power、WNS 或 TNS；不把设计级标量混同为节点/关系恢复。

关系结构恢复只作为可选辅助目标，不是 EDA 默认目标。只有当某个来源的关系端点覆盖和标签覆盖通过审计时，才允许打开
reconstruction loss；节点 PPA 和设计 PPA 任务默认使用 `G -> S_e -> y_task` 的任务损失。

## 当前已验证成功与缺口

已验证成功：V1-C 独立 CPU smoke、真实 SKY130 pair 的 CUDA 前向/反向、CUDA dense-memory 优化后的训练路径、
节点级 area 任务的 609 个 CircuitNet eligible pair 筛选，以及单任务节点/设计/关系 head 的张量和反向闭环。
这些结果证明工程接口和优化过程可运行，不证明跨设计 PPA 泛化。

数据缺口：5,772 个 pair 中 fine node area 仅覆盖 4,547,889/7,998,693 个节点，power 覆盖 1,924,899 个，
timing 覆盖 206,289 个；225 个 pair 超过 dense `max_nodes=4096`。设计级 area/WNS/TNS 目前仅有 TimingPredict
的 21 个 pair。非 TimingPredict 的大量 timing arc 端点不能映射到当前 `cell/net` 输入节点，因此不能直接用于关系任务。

因此，当前可接受的证据链是：先报告节点任务和已对齐关系任务的指标，再报告可选 reconstruction ablation；不能用
稠密 `r_null` accuracy 或图恢复 loss 代替 PPA downstream 结果。

## 数据集必须处理的问题（2026-10-23）

在进入正式节点/关系实验前，必须处理以下数据问题：

- **标签覆盖不均衡：** 5,772 个 pair 的 fine node area 覆盖 4,547,889/7,998,693 个节点，power 覆盖
  1,924,899 个，timing 覆盖 206,289 个；所有连续损失必须使用字段级 mask，不能把缺失值当零。
- **设计级零值语义：** `labels.json` 中 power 字段在所有来源都存在，但很多来源的零值是默认活动或无效结果；
  power 监督必须保留工具有效性和来源 metadata，不能只依据字段存在或数值非空。
- **关系端点不一致：** 非 TimingPredict 的大量 timing arc 端点不能映射到当前 `cell/net` 节点；未映射关系必须
  被排除，或先把输入图提升为 pin-level/经过验证的 cell-level aggregation，不能直接构造关系 target。
- **关系类型不完整：** 输入 G 有 `r_null/cell_to_net/net_to_cell`，fine relation 主要只有 `cell_to_net/timing_arc`；
  `net_to_cell` 缺失不能被当作负关系标签。
- **执行规模协议：** 图规模会影响 dense V1-C 的显存和 batch 组织，但不构成数据集正确性问题；是否使用
  整图、降低 batch、分块或稀疏实现属于执行配置，不得因此修改原始图或补造标签。
- **监督来源分层：** TimingPredict 只有 21 个 pair，area/WNS/TNS 设计级标签只在该来源存在；CircuitNet、EPFL、ITC99、
  OpenLane-local 主要适合 area/结构或 design power 子任务，不能合并为同一 timing 数据集。
- **数据划分：** 当前按 manifest 顺序的 80/20 split 只是 smoke 协议；正式结果必须按 design/source 去重后固定 train/valid/test，
  避免同源变体、重复网表或来源分布造成泄漏。

## 当前边界

研究目标是验证受限关系族上的关系保持点集编码：固定维度点集 `S_e` 是否能够近似保留图信息，
并生成与目标图相近的 `G'`。不宣称任意全关系图都能被固定维度点集无损表示。图表示为节点特征
`X` 和有序关系张量 `R`；无边关系若存在，也必须作为显式关系状态记录。

## 已确认约束

编码器输出 `S` 应对节点排列保持等变，关系解码器应按相同排列变换。全关系批量计算的基本存储规模为 `O(n^2)`，迭代 `T` 次时至少需要报告 `O(T n^2)` 级别的点对计算。

## V0 基线实现（历史对照）

V0 按 `for-agent.txt` 的极简基线拆分为独立模块：`ENCS` 和 `ENCR` 负责 MLP 预编码，
每个演化层独立拥有 `PAIRATTN`、`ENCO`、`Gate` 和 `LayerNorm`，终态使用独立的
`SETATTN_out` 与 `PAIRATTN_out` 解码节点和有向关系。实现位置为 `code/v0/`，隔离测试位置为
`test/v0/`，不会复用旧版 `code/*.py` 的模型连接。

V0 当前使用连续节点向量和连续关系向量，因此节点类型数、关系类型数均不适用且不可数；
若后续接入离散图，必须重新声明节点类别、关系类别和显式 `r_null` 的编码方式。
V0 已通过 CUDA 前向、反向、padding mask、有限数值和排列等变性 smoke，并通过
`demo/demo_v0.py` 的独立前向 demo。原公式中的 `similar` 尚未指定具体形式，当前只保留可替换
接口；当前连续 V0 的训练主损失使用 masked MSE，余弦相似度保留为评估指标，不能视为训练目标。

V0 嵌入还原实验使用低秩连续关系族：节点特征经过固定源/目标线性映射生成有向全关系张量，
训练/验证 split 使用不同节点采样但共享关系生成规律。实验入口为
`script/train_v0_reconstruction.py`，数据位置为 `dataset/v0_reconstruction.py`，训练实现为
`code/v0/training.py`。该实验只验证 `G -> S_e -> G'` 的可训练闭环；低秩数据上的短时 smoke
不能替代独立随机关系容量边界、真实图数据或多种子实验。一次 50 epoch、256/64 张训练/验证图的
正式运行达到验证 MSE `3.4476e-02`，节点 MSE `9.5469e-03`，关系 MSE `2.4929e-02`；
该结果只对应当前低秩生成机制和单个随机种子。

真实数据实验入口为 `script/train_v0_real.py`，转换器为 `dataset/v0_real_molecule.py`。ZINC
使用 21 类节点、3 类真实键和 1 类显式 `r_null`，得到 4 类稠密关系；QM9 使用 5 类节点、
3 类真实键和 1 类显式 `r_null`，同样得到 4 类稠密关系。稠密 one-hot 节点/关系作为 V0 的
连续输入，padding 只由 `node_mask` 排除，不替代 `r_null`。当前已通过 ZINC 和 QM9 batch
读取 smoke，并完成一次 ZINC train/val 正式还原训练；该结果尚未包含官方 test split、多种子
或基线比较。

当前 V0 训练损失在 MSE 主项之外允许加入可导的关系相近度辅助项：
`L = L_node_mse + L_relation_mse + lambda_similarity * (1 - cosine(R', R_target))`。
关系准确率不参与反向传播，只作为离散评估指标。`lambda_similarity` 是实验参数，当前 smoke
使用 `0.1`，不能视为已确定的最终权重。训练进度按 5 秒时间间隔节流输出，epoch 汇总始终保留。

当前阶段定位为算法机制验证，不进行多随机种子实验，以节约实验时间。优先验证单种子下
`G -> S_e -> G'` 的真实图还原、关系相近度辅助损失是否有作用，以及官方 test split 上的
节点/关系离散还原指标；多种子和统计比较延后到算法机制确认之后。

演化轮数由 `layers` 控制。增加 `layers` 会增加独立的偏差计算与点集更新轮次，模型参数和
计算量都会增加；不同轮数必须重新训练，不能直接复用其他轮数的 checkpoint。当前下一项机制
实验采用 `layers=4`，与 `layers=2` 使用相同数据、损失和单种子配置进行比较。

单种子 ZINC train/val 对照中，加入 `lambda_similarity=0.1` 后，epoch 30 的关系 MSE 为
`6.9146e-03`，此前无辅助项结果为 `7.0287e-03`；节点 MSE 为 `2.8112e-05`，与此前

## 第一版实现规格

当前组件规格：缩放点积 `ENCS`、单头 `SETATTN`、演化 `PAIRATTN`、独立终态
`recovery_pair`、`ENCR` 关系对齐和

## 已验证的 ENCS 候选

`code/encs.py` 实现了给定的缩放点积 `AttentionSmooth`：先计算 `S_bar = MLP(X)`，再用 `softmax(S_bar @ S_bar^T / sqrt(d)) @ S_bar` 得到低频分量，最后对高频残差和 `epsilon * noise` 做逐节点 `L2` 归一化并乘以 `beta`。输入和输出均为 `[B, v, d]`；实现支持外部传入噪声，以便复现实验和检查同步排列下的逐样本等变性。

随机噪声在固定样本下需要随节点排列同步，普通独立重采样只能保证分布意义上的等变性；`beta`、`epsilon` 和 MLP 结构仍需后续审核。

## 下游任务统一视角

当前框架将下游任务表示为：

```text
G(X,R) -> S_e -> G'(X',R') -> y_graph
```

目标图预测首先由 `S_e` 解码得到 `X'` 和 `R'`：节点级任务评估 `X'`，关系级任务评估 `R'`，
图级任务再对 `G'=(X',R')` 或 `S_e` 执行置换不变聚合。节点/关系预测不是脱离图恢复的独立
分类任务，而是目标图 `G'` 的组成部分；图级任务可以不逐项精确重构全部关系，但它所需的
局部结构和全局统计量必须先保存在 `S_e` 或 `G'` 中。

状态说明：上方 V1 smoke 描述是历史阶段记录；随后已完成正式 ZINC 训练和 test 评估，当前
主线状态以本段和 `具体设计.txt` 的 V1 规格为准。

## V2-EX 深度与稳定性诊断

V2-EX 的“深度”是共享向量场重复应用的迭代步数 `T`，不是具有独立参数的层数。第 `t` 步记录原始场
`D_t=DeltaS_t`、实际相互作用 `eta*D_t`、坐标更新、噪声和坐标范数。有效坐标 RMS 定义为
`||D_t||_2/sqrt(有效节点数*坐标宽度)`；交互 RMS 再乘 `eta`；相对交互量为
`eta*||D_t||_2/||S_t||_2`。保留原噪声机制，分别记录确定性场与实际注入噪声；当自适应噪声自然退出后，
才能进一步检查固定点残差。不能为了看收敛而默认将验证噪声置零，也不能仅凭更新 RMS 小或噪声衰减判定收敛。

深度 sweep 采用最大 T 训练时最低完整训练 loss 的共享权重，在训练集分别截断到若干前缀；各前缀使用
相同固定种子产生的随机噪声前缀及原有自适应噪声尺度，并仅统计可达 pair 跳数。该协议能测同一动力学
轨迹的深度截断效应，不等价于每个 T 独立训练后的最优性能比较；
若要回答后者，需另做同 seed、同预算、同数据的独立训练对照。

## V2-EX 通用图算法改进方向（2026-10-27，待审核）

本节按用户要求讨论通用图嵌入能力；只整理研究思路，不修改代码、训练目标或已有架构。核心依据为用户维护的
`具体设计.txt` 第 15 节与当前 `code/v2_ex/`，不是将 CLRS 跳数预测规则写入模型。

核心原则：完整图 G=(X,R) 条件化共享向量场 D_theta(S,R)，通过 S_next=S+eta*D+noise 演化节点坐标；
H=SETATTN(S) 是上下文，Attn-Pair 从 H 提取当前隐式关系，f 结合显式关系、隐式关系和相对位置生成偏移。
最终读出只通过终态 S/H，不直接读取原始 R。S 的累计尺度不得被逐节点归一化覆盖；噪声服务于对称性破除，
而非默认关闭的训练增强。T 是同一场的求解步数；当前 dense 全局交互不能解释为每步仅跨一条图边。

关键推导：对同型节点的环图，若噪声退出后的确定性、置换等变更新对固定 G 具有全局唯一吸引固定点，
该固定点必对环图的所有自同构保持不变，从而各节点状态相同。只读两个节点状态的 decoder 将不能区分
邻接与非邻接。因此候选应追求保留对称性破除结果的局部稳定或多个等价稳定解，不能直接采用全局唯一收缩。
该结论依赖当前 node-state-only 读出和不提供额外节点身份的假设，不排斥图条件化稳定动力学本身。

方向 A：信息保真的聚合。当前每个有效源节点含 r_null 都进入 sigmoid gate 后的单一平均，且除数为有效节点数。
当少数源消息携带关键信息时，存在稀释及不同消息相互抵消的风险，但尚未实测其为失败主因。候选为少量并行
关系条件路由/聚合通道，保留消息数量或总强度，融合后仍生成同一个 DeltaS；不删除 r_null、不读取 hop 标签，
不把所有关系强制成无向对称。单用 softmax 替换 mean 会丢掉总量信息，不能视为自动解决。

方向 B：限制放大，同时保留传播。诊断更新映射 I+eta*J_D 的局部敏感性，以及 QK、pair 乘积与 f 的尺度增长。
候选只在上下文/消息映射中控制增益，保留坐标 S 的原始残差路径；可研究低耗散的通道耦合与状态条件松弛。
不把“所有方向强收缩”“噪声关闭”“gate 逼近零”当作收敛方案。反对称通道变换不等于把图中正反向关系
设为反对称；连续时间稳定性也不自动保证当前 Euler 离散稳定。不能由内部 T 的场增大直接断定优化 step 退化原因。

方向 C：让节点区分在交互后存活。保留原噪声机制，先测相同噪声下的排列等变性、不同噪声下的任务读出稳定性，
以及节点差异通过多个更新后是否被压平。若证据支持遗忘，可研究 S 内部不同更新速率的记忆通道；它仍属于
节点状态，不引入固定编号，不把随机特征当成标签。新增状态/门控属于较大架构候选，须另行审核和控制参数预算。

方向 D：减少对固定读出时刻的依赖。候选在适当区间采样终止 T，每次仍只对该次终态监督，而不是强迫所有早期
状态都立即完成任务。先做保持原噪声机制的超训练步数 rollout 诊断；随机终止训练是训练协议变化，尚未执行。
若更长 rollout 才出现失稳，应先区分场本身与离散求解器的问题，再讨论自适应步长；缩小步长不等于原始场残差归零。

优先级建议：先审计聚合的信息保留和局部放大，再选择 A 或 B 单项候选；C 属于后续更大改动，D 可作为通用计算
时间鲁棒性实验。通用判据包括对称图可区分性、结构扰动响应、不同 N/密度的消息尺度、节点差异保留、非零噪声下
延长 T 的稳定性，以及同一编码器在不同节点/关系/图级读出上的有效性。不能用单一 hop accuracy 代替通用能力证据。

研究参考（用于启发，不表示论文结论已在 V2-EX 上成立）：Alon & Yahav, ICLR 2021, arXiv:2006.05205；
Corso 等, NeurIPS 2020, arXiv:2004.05718；Abboud 等, IJCAI 2021, arXiv:2010.01179；
Bai 等, ICML 2021, arXiv:2106.14342；Gravina 等, ICLR 2023, arXiv:2210.09789；
Arroyo 等, arXiv:2502.10818。具体的增益控制、聚合方式、状态拆分和训练区间均未获得实现授权。

## V2-EX 分流程诊断清单（2026-10-27，方案）

本清单是观测建议，未加入训练代码或 loss，也不改变原架构、噪声和当前只看训练集的实验范围。
区分优化步 k 与内部演化步 t；固定训练集探针图和噪声种子，记录 checkpoint、N、关系分布、eta 和有效 mask。
对坐标类张量使用有效元素 RMS，按图记录后汇总 median/p95/max；对关系类张量使用有效 pair 数归一化，
不把 padding 或 r_null 当成同一种 mask。总体指标和按图指标分开报告，避免大图支配统计。

| 流程 | 建议统计 | 要回答的问题 |
| --- | --- | --- |
| 输入及 ENCS | 输入类型数/频次；S0 的 RMS、节点间中心化方差、点对距离分位数；ENCS 参数梯度 | 同型节点是否本来就相同；破除对称之前不能把同型节点相同判为故障 |
| ENCR | 各关系编码 RMS、关系类型之间的距离/余弦；关系条件通道梯度 | 显式关系是否被编码区分；关系编码不同不等于下游 f 真正在使用它 |
| SETATTN | Q/K/V RMS、QK logits 范围/行标准差、attention 熵与有效 source 数；H-S RMS、H/S 节点散度 | 注意力是否极端饱和、上下文是否淹没原状态；attention 图样本身不能证明因果作用 |
| Attn-Pair | prod/diff/value/H_j/H_i 各分支 RMS；pair 通道方差；抽样 pair 的有效秩；对 H_j/H_i 的 JVP | 某些分支是否被忽略，pair 对两个端点是否都有响应；低秩本身不是任务失败的充分条件 |
| 三模态 f 与 route | 按关系类统计未门控 offset、gate、gate*offset 的 RMS；gate 分布及饱和比例；f 对关系/pair/pos 分支的尺度归一化敏感性 | f 是否只使用一个条件；不能仅凭 gate 大就认为实际消息大 |
| source 聚合 | 聚合前消息范数之和、合向量范数、抵消系数；按关系类的总贡献和每 pair 均值；与 N/关系密度关系 | 稀释来自有效源数、消息抵消还是门控；r_null 数量多与单条贡献大必须区分 |
| 坐标演化 | raw field RMS、eta*field RMS、真实更新 RMS；质心、中心化 RMS、点对距离分位数；相邻步场方向余弦；局部扰动增益 | 共同平移、尺度扩张、局部振荡、节点差异消失分别发生在哪一步 |
| 自适应噪声 | concentration、sigma 的分位数和零比例；注入噪声 RMS、与交互 RMS 的比值；不同 noise seed 的读出方差 | 噪声是否按原设计退出、是否仍主导更新；不通过强制零噪声制造“稳定” |
| 最终 SETATTN/Attn-Pair/head | 各阶段输入输出 RMS/节点或 pair 散度、预测分布、读出对 S 的敏感性；任务 loss/accuracy/MAE | 信息是没进入 S，还是经过最后上下文/pair/head 后不再影响预测 |
| 反向与优化器 | 各模块裁剪前梯度 RMS/范数，S_t 的梯度；全局梯度裁剪比例；实际参数更新相对量；同图同噪声更新前后 loss | 哪个模块首先出现不稳定，变化发生在前向、反向还是优化器更新；梯度裁剪不等同于限制 Adam 参数步幅 |

抵消系数按有效源定义：c_i=||sum_j m_ji||/(sum_j ||m_ji||+epsilon)，其中 m 为已门控消息。
c 接近零只表示抵消，结合 raw field、节点可区分性和读出结果才判断是否有害；不设固定“合格阈值”。
局部增益可以用随机方向 JVP 估计 ||(I+eta*J_D)v||/||v||，无需构造完整 Jacobian；单个随机方向不能给出
最坏方向增益，单步增益大于 1 也不等于长期发散证明。完整轨迹扰动检查必须同步未来的噪声样本，并保留
原状态相关噪声尺度，否则噪声差异会混入传播敏感性。对纯 D 的导数观测不意味着运行时关闭噪声。

通用信息传播检查：在固定图上观测节点状态的局部微扰如何影响其他节点/最终读出；可按输入图距离、度数、
节点角色分组展示敏感性，只用于解释，不作为坐标输入或 loss。当前全局交互不直接套用局部 MPNN 的传播半径定理。
离散关系用合法的另一张输入图做对照，不给 one-hot 输入随意加连续扰动并将其当作真实图；数据标签须与图一致。

优先落地最小集：按 t 的 field/interaction/noise/centered-coordinate RMS；按模块的 gradient/update ratio；
gate 饱和与实际消息量；聚合抵消；训练预测分布。低成本曲线定期在少量固定训练图上跑；JVP、秩和多 seed
检查低频执行，不保存完整 N*N*d 消息轨迹、不构造全 Jacobian。诊断运行使用 CUDA，独立 RNG，观测值不加到 loss。
对于优化 k=900--950 的已知退化区间，应逐步记录 batch loss/accuracy、梯度和真实参数更新；定期保存模型、
AdamW 状态及 Python/PyTorch/CUDA RNG，才能从退化前精确复现，而不是仅保存最终权重。
