# 算法描述

## 最新实验状态（2026-10-26）

DAC2027 virtual timing 与 physical artifact 已完成首轮数据构造。Virtual timing 有效训练设计为 `3796` 个，
使用 source-family 分层 split `3036/378/382`；physical OpenROAD 本轮新成功 artifact 为 `3211` 个，另有 `559` 个
缓存成功 artifact，当前有效 physical 三件套共 `3770` 个；成功定义为同时具备 final ODB、DEF 和 SPEF，超过
`max_nodes=2048` 的设计不进入 dense physical 队列。

V1-C 的 query-conditioned relation head 已通过前向/反向接口验证，但 Virtual Arc Delay 长程稀疏关系实验没有形成
稳定正式结果，当前不继续追加 V1-C 训练。V2 已先完成 topology-only dense multi-hop 关系实验：输入为有向节点/关系向量，
读出为 `PAIRATTN` 节点对表示与 `ENCR` 关系表示的融合，目标为全 pair `reachable` 和可达 pair `min_hop`。
V2 单图记忆实验显示该机制可以学习部分全局结构，但尚未实现完整有向路径坐标化。

## 当前电路实验接口（2026-10-23）

当前电路实验的输入与输出固定为：

```text
netlist graph G -> GSG V1-C -> labeled graph G'
```

输入 G 来自固定 SKY130 网表：节点是 `cell/net` 两类可数类型，关系是
`r_null/cell_to_net/net_to_cell` 三类可数关系；`r_null` 是显式关系，不是 padding mask。
目标 G' 由本地 PPA fine label 组成：节点包含 area、power、timing coverage 等带有效性字段的
连续标签，关系包含 timing arc、delay、slack、critical 等标签。缺失标签保留 `has_*` 语义，
不能直接填零后当作真实监督。

另有已接入的 DAC 数据接口，但它不是上述 SKY130 `cell/net` pair 的替代命名：mapped-v2
输入节点为 `standard_cell/net_bit/primary_input/primary_output/const`，关系为
`r_null/drive_to_net/net_to_load`；pin timing-v1 输入节点为 `cell_pin/primary_input/
primary_output/primary_inout`，关系为 `r_null/cell_arc/net_arc`。mapped PPA 与 pin timing
是两个任务数据集，不能把 pin arc 标签强行映射成 cell/net 的 `timing_arc`。

## 电路表征建模主任务调整（2026-10-25）
完整电路图始终作为输入，不通过隐藏边或删除关系制造图任务。节点属性相同而拓扑、方向、多跳路径或功能变化时，目标应随完整电路结构变化。
节点 area、internal power 和 leakage power 只作局部属性控制实验；graph area/graph total power 如果由节点预测求和，也只作聚合评估。
DAC 主任务改为完整图级 QoR、path-level timing、Yosys/ABC candidate ranking 和 Yosys equivalence/formal 驱动的功能/结构任务。
Yosys/ABC + OpenSTA 负责 synthesis-level 标签；OpenROAD/OpenRCX/OpenSTA 负责 physical-level PPA 验证。两级结果分开报告。

## Virtual timing V2 待设计边界（2026-10-25）

V1-C 的 query-conditioned relation head 已完成工程反向 smoke，但在 Virtual Arc Delay 的长程、稀疏 Launch-Capture
关系上尚未表现出稳定训练收益。该任务与局部 `CELL_ARC` delay 不同：每个 design 只有少量有效查询，路径跨越多级组合逻辑，
节点演化后再做关系读出可能造成 query 信号稀释。

因此登记 V2 研究问题：**如何在不破坏 `G=(X,R) -> S_e` 目标的前提下，让长程稀疏 query relation 获得直接、可保持的
路径结构信息。** V2 必须继续使用原生节点/关系输入，query node/`r_query` 只作为任务条件，不读取 delay/slack/criticality
等 target-derived 字段。具体路径记忆、稀疏关系读出、层次化传播和辅助监督均待方案审查，不能将候选细节当作已确认算法。

## V2 Dense Multi-Hop 实验状态（2026-10-26）

### 输入与标签

当前 dense 数据集为 `dataset/v2_dense_multi_hop_directed/`，使用 DAC2027 timing graph 的 topology-only 输入，
`max_nodes=512`，split 为 train/val/test=`1298/172/163`。节点输入字段为：

```text
node_kind, node_direction, node_cell_family, node_is_sequential
```

每个有序 pair 的关系向量状态为：

```text
r_null
CELL_ARC_forward / CELL_ARC_reverse
NET_ARC_forward / NET_ARC_reverse
```

`r(i,j)` 与 `r(j,i)` 使用不同的方向关系向量。标签只由 timing graph topology 计算：全 pair
`reachable`，以及 `hop_valid` 下的 `min_hop`；不使用 delay、slack 或 criticality。

### 模型数据流

```text
X -> ENCS -> node states
R -> ENCR -> directed relation states
node states -> PAIRATTN(i,j)
PAIRATTN(i,j) || ENCR(r_ij) -> relation head
-> reachable / min_hop
```

`PAIRATTN` 只读取有序节点对和全局节点上下文，不直接读取关系向量。当前 20 epoch valid 结果为
reach accuracy `0.8475`、hop MAE `1.5925`；单图 1000-step 记忆实验为 reach accuracy `0.8624`、
hop MAE `1.0908`、embedding distance-hop Pearson `0.5723`。这些结果证明存在部分全局结构学习，
但不能声明已经形成完整有向全局坐标。

### 当前边界

当前 dense 结果是全局结构机制实验，不是 STA delay 结果。Electricity Meter 仍保留给 sparse
Launch-Capture path-delay 任务；传统 STA 对齐所需的逐边 slew/load/RC/PVT 输入尚未完成，不能把
`pin_electrical` proxy 结果写成完整电气 timing 预测。

## 下游输入增强实现（2026-10-24）

作为可选的 mapped PPA 输入增强，已接入原始处理目录中与 mapped-v2 节点严格同序的
`features_ppa_circuit_v2/total`。该 artifact 覆盖 `5,613` 个设计，包含 16 个非标签特征：Liberty
输入/输出电容、pin role/timing arc 统计、net sink capacitance、fanout 以及 cell output 负载聚合。
`rich` profile 对这些非负结构特征使用 `log1p` 后拼接到原 25 维节点输入，节点宽度为 `41`；不读取
power label、OpenSTA power report 或 power table，因此不存在标签泄漏。

作为可选的 pin timing 输入增强，`pin_electrical` profile 从同一 NangateOpenCell Liberty 读取 `cell/pin
capacitance`，按 timing 节点的 `cell/pin` 名称和 mapped graph cell type 对齐，填入原有
`node_pin_cap` 通道；同时从当前 `edge_index` 计算 `CELL_ARC/NET_ARC` 的有向入度和出度，使用
`log1p` 后追加到节点输入，节点宽度由 `25` 变为 `29`。缺失或无法对齐的 pin 保留零值，并通过
`metadata.pin_cap_valid_count` 暴露有效数量；不把 delay、slew 或 timing label 反推为输入。

delay 训练仍使用现有 V1-C 和 global PAIRATTN，只把有效 delay target 改为
`(log(delay_ns)-mean)/std`，在该空间计算 Huber loss，预测后 `exp` 回 ns 再计算 MAE、RMSE 和 MAPE。
这改变的是目标尺度和输入字段，不改变 GSG 的编码器、Evolution、Decoder 或 PAIRATTN 算法结构。

真实 toggle 标签目前来自旧的 cell-only graph，节点名与当前 mapped-v2 的 flattened cell/net 节点不一致，
因此暂不拼接到当前 predictor。要解决 switching 的 activity 缺口，仍需生成与 mapped-v2 节点和
`edge_index` 同序的 activity/toggle artifact；当前 `rich/liberty` 只代表输入 schema smoke，必须在新目录
重新训练后才能与旧 baseline 比较。冻结输出目录为 `runs/dac2027_timing_*_pin_electrical_log_max2048_full/`。

## 连续 PPA 训练与主表协议（2026-10-24）

当前冻结版本为 `dac2027_v1c_max2048_logspace_20261025`，结果清单见
`runs/dac2027_max2048_release.json`。它固定使用现有 V1-C/global PAIRATTN、mapped rich、timing pin electrical、
log-space masked Huber 和 max2048 执行边界；fall 只使用正值 channel-specific mask。

对 area、internal/switching/leakage/total power 和 rise/fall/worst delay 这类正值连续回归，训练尺度与评估尺度分离：
有效标签先在 train split 上做 `log` 变换和 mean/std 标准化，训练使用 masked Huber；预测还原为原始 `um^2/W/ns` 后，
再计算 MSE、RMSE、MAE 和 MAPE。该协议稳定长尾物理量的训练尺度，不改变 V1-C 的图编码、Evolution、Decoder 或
relation PAIRATTN 读出。

执行层面允许使用 DataLoader worker/pinned memory/non-blocking CUDA copy、复用 worker、eval inference mode 和高精度
matmul；这些只优化数据搬运与 kernel 调度，不改变模型结构、目标定义或指标语义。

delay 的 `pin_electrical + log-delay` 已实现并用于当前新队列；mapped area/power 的新训练需遵循同一协议，旧
raw-scale `*_full` checkpoint 只作为历史 baseline，不能把其标准化 loss 与新 log-space loss 直接横向比较。真实值为零的
power prediction 不进入 MAPE 分母，但保留 zero count 和 raw absolute metrics。

主表按任务粒度统计：节点 area/power 只在有效节点上计算，delay 只在有效 `CELL_ARC` relation 上计算；MAPE 以有效
prediction 为分母，建议主报告使用设计级 macro `mean ± std`，同时报告 valid designs、valid predictions、raw-space MSE
和 RMSE。主表以单个 design 的完整 model-forward 时间 `ms/design` 为主要成本指标，并按节点数分桶报告均值/中位数、标准差
和 peak GPU memory；节点任务的 `us/input_node`、delay 任务的 `us/dense_pair` 和 `us/valid_CELL_ARC` 只作规模归一化
辅助指标。它们是总 design forward 时间的摊销，不表示单个节点或 relation 被独立执行；计时不包含数据加载、loss 和 backward。单 seed 的标准差
表示测试设计间波动，不表示多种子置信区间；多种子实验再另行报告 seed-level `mean ± std`。

耗时分析必须保存每个 design 的 `(N, t_design)` 配对，而不是只报告 `t/N` 或平均值。当前 dense V1-C/global PAIRATTN
使用 `t_design(N)=alpha+beta*N+gamma*N^2` 作为规模拟合基线，报告 `alpha/beta/gamma`、R² 和残差；`N^2` 项用于验证
pair/state 张量的实际成本。delay 的有效 `CELL_ARC` 数量可作为第二解释变量，但不替代主节点规模关系。

当前 N² V1-C 的可接受执行协议为 `max_nodes=2048`，而不是无界 dense 图：mapped/timing 分别覆盖 `4680/5613` 和
`4094/5613` 个设计。`max_nodes=4096` 的 timing rise 已在 backward 阶段触发 A100 40GB OOM，因此 4096 只保留失败审计，
当前不作为正式实验边界。超过 2048 的图保留在数据集 manifest 中，不静默删除；后续若要覆盖它们，需要经过独立的
chunked/sparse pair-state 实现和显存验证，不能把 SDPA/FlashAttention 对单个 QK kernel 的优化误认为解决了完整 N² 图。

## 分层 N² 建模探索（待审核，不进入当前主线）

当前 V1-C 的 `SETATTN`、`PAIRATTN` 和 `EvolutionLayer` 都会产生显式 pair/state 张量；只替换单个 QK kernel
不能消除完整 dense `N^2` 的显存开销。为覆盖 2048 以上的大图，保留现有 V1-C/global PAIRATTN 语义的候选方向是：

```text
G -> topology-only clusters -> local V1-C/PAIRATTN
  -> cluster token pooling -> cluster-level global context
  -> local context injection -> sparse relation PAIRATTN readout
```

建议的两级结构为：每个 cluster 内使用局部节点/关系上下文，cluster token 再进行全局 attention；同 cluster 的
`CELL_ARC` 由局部 pair readout 预测，跨 cluster 的 `CELL_ARC` 使用两个端点 embedding 和两个 cluster token
进行有序 pair readout。`NET_ARC` 仍只提供拓扑，不进入 delay loss。目标粒度仍是有效 relation，不改成节点 delay。

候选复杂度从 `O(N^2)` 转为 `O(sum(cluster_size^2) + K^2 + E_target)`；其中 cluster size 先考察 64/128，
`E_target` 是有效 `CELL_ARC` 数量。对更大图还需要递归 super-cluster，不能仅依赖一次 cluster-level dense attention。

数据契约必须保存 `cluster_id`、cluster members 的原节点顺序、cluster graph edge、跨 cluster edge 和反向映射；
所有 cluster 必须由图结构、节点类型和合法输入特征生成。外部已有 `labels_ppa_cluster_v2` 使用
`logic_cone_bfs_max64_v1`，但只覆盖部分设计且包含 `y_power` cluster target，因此只能作为分区实现参考，不能直接作为输入。

该方向当前只写入设计探索，不修改 `code/v1_c`，不改变正在运行的 `max_nodes=2048` 实验，也不产生正式性能结论。

## 下游任务与输入图视图

当前系统支持的是“同一物理数据的任务特定图视图”，不是要求所有任务共享同一个节点集合：

- **连续合成图：** 输入为连续节点和连续有向全关系；支持节点/关系重构，以及 `factorized` 和
  `two_hop` 生成的节点二分类、关系二分类。
- **分子图：** ZINC 使用 21 类节点、4 类稠密关系，QM9 使用 5 类节点、4 类稠密关系；支持
  节点类型和真实键/显式 `r_null` 的重构。
- **Cora masked graph：** 输入节点为 1,433 维特征、关系为 `r_null/observed citation`；支持
  7 类节点 subject 分类和隐藏边/匹配非边查询。
- **GSG SKY130 cell/net 图：** 支持节点 area、四类 instance power、timing observations/arrival/slew，
  设计 area/total power/WNS/TNS，及 `cell_to_net`、`timing_arc` 二分类关系；PPA multi-task
  还支持 4 类关系类别和 `delay/slack/critical` 连续 timing 标签。
- **DAC mapped-v2 图：** 支持 mapped-cell area 和四类 mapped-cell power，以及由节点物理求和得到的
  设计级 area/power。
- **DAC pin timing-v1 图：** 支持 `CELL_ARC` 的 rise/fall/worst propagation delay；`NET_ARC`
  目前只作为拓扑，不提供 delay 监督。

其中 GSG cell/net、DAC mapped-v2 和 DAC pin timing-v1 是三个不同的电路图视图。节点类型、关系
类型和 `r_null` 语义必须在每个任务 manifest 中单独声明；没有端点对齐的标签不得进入监督。
DAC 已接入 V1-C 单任务训练入口：mapped area、四个 mapped power、pin rise/fall/worst delay
分别使用独立模型和 checkpoint；graph area/total power只作为节点预测聚合评估。

旧 raw-scale DAC predictor test 结果保存在 `runs/dac2027_area_full_max1024/`、
`runs/dac2027_power_*_full/` 和 `runs/dac2027_timing_{rise,fall,worst}_full/`；八个历史任务均有最终
`test.json`，但不能代表当前冻结 log-space 版本。当前冻结结果输出到 max2048 目录；新结果应优先读取
`runs/dac2027_max2048_release.json`，旧 raw-scale/1024 目录仅作历史对照。

相对误差评估按单个 prediction 与对应 true label 计算，不进行设计级先验平均：
`relative_error=abs(prediction-true)/abs(true)`。每个任务的逐预测结果写入 `relative_errors.jsonl`；真实值为零时只保留
绝对误差并将 relative error 设为 `null`，以避免零分母产生伪指标。

## DAC predictor 当前输入充分性边界

现有 DAC 结果应解释为固定输入 schema 下的 baseline。mapped-v2 当前输入包含节点类型/family、drive strength、
sequential/reset/set 属性、pin 数量和 `drive_to_net/net_to_load` 拓扑，但没有 numeric activity/toggle、频率、
input slew 或 load/capacitance。pin timing-v1 当前节点包含 pin capacitance、方向、cell family 和 drive strength，
但 `CELL_ARC` 边没有 arc-specific slew、load 或 transition 条件。

因此，switching power 的高相对误差首先是输入信息不足问题；delay 虽然目标粒度正确地保持为 relation-level `CELL_ARC`，
但缺少边条件会限制预测。改进实验必须先完成字段来源审计、schema/tensor/mask 测试，再按单任务重新训练；不得把新增字段
默认值或标签反推值当作真实输入。

## 下一版数据集需求

- mapped power：cell/net/pin 的 activity/toggle、频率、slew、load/capacitance、逻辑状态和来源 metadata；
- pin timing：每条 CELL_ARC 的有序 source/target pin、arc type、rise/fall 条件、input slew、output load/capacitance、
  PVT/corner 和有效 mask；
- 所有 edge feature 与 `edge_index` 逐条对齐，所有缺失字段显式 mask；输入条件和标签条件必须使用同一 tool/corner/frequency；
- manifest 记录每个字段的单位、来源、覆盖率、零值数量、设计去重规则和固定 split。只有完成这些审计后，switching/delay 新结果
  才能与当前 baseline 正确比较。

## DAC-EDA 下游任务边界

`dac2027` 的 E-DAC 主任务不是泛化的“所有电路任务”，而是以下八个独立单模型目标和两个聚合评估：

1. mapped-cell Liberty area；
2. mapped-cell `internal` power；
3. mapped-cell `switching` power；
4. mapped-cell `leakage` power；
5. mapped-cell `total` power；
6. pin-level `CELL_ARC` rise propagation delay；
7. pin-level `CELL_ARC` fall propagation delay；
8. pin-level `CELL_ARC` worst propagation delay。

聚合评估为 graph area（由 area 节点预测求和）和 graph total power（由 total power 节点预测求和）。

mapped-cell area、四类 power 和三个 delay 通道分别训练；graph area 与 graph total power 分别由对应
节点预测求和得到，只用于评估，不进入其他任务的训练 loss。

`NET_ARC` 当前只表示理想互连拓扑，不进入 delay loss。节点/边恢复指标是辅助表示证据，不能
替代上述八个主任务。DAC Agent Phase 2 另外定义四个真实 EDA 优化任务：T1 timing closure、
T2 area compression、T3 power compression、T4 multi-objective PPA；它们需要真实 EDA flow
和等价检查，不能等同为静态 PPA 回归任务。

统一 pair 数据位于 `dataset/paired_graphs/`，当前 manifest 有 `5,772` 个完整 pair：
open_verilog `5,021`、CircuitNet `627`、EPFL `26`、ITC99 `76`、OpenLane-local `1`、
TimingPredict `21`。这些数量是来源审计后的正式统计，不包含 CircuitNet 的 264 个 partial-label
额外目录。

当前实验准备边界：V1-C 的点集编码、关系演化、自适应噪声和独立解码结构保持既有规格；PPA
监督接口已经完成短 smoke；DAC 单任务实现通过字段级 mask、训练统计标准化和 batch padding 处理缺失值。
当前正式 predictor 使用冻结 source-family split、CUDA 和冻结 `max_nodes=2048`，每个任务独立报告结果，
不能把一个任务的结果外推到其他任务。

首个真实 pair audit smoke 显示节点类型为 `cell/net`，关系标签至少包含 `cell_to_net`，部分
来源包含 `timing_arc`；area 覆盖率是来源相关的，power/timing 覆盖率可能为零。该结果说明训练

full audit 结果进一步确认：TimingPredict 的 21 个 pair 均有 power/timing 标签；open_verilog
为混合覆盖；CircuitNet 627、EPFL 26、ITC99 76 和 OpenLane-local 1 个 pair 当前没有非零
power/timing fine-node coverage。当前最稳妥的实验准备是先做结构/area 子任务或按来源建立独立
监督子集；power/timing 任务必须只使用对应 `has_*` 字段有效的 pair。

## EDA downstream 任务边界（2026-10-23）

EDA 主目标不是恢复完整图 `G'`，而是验证编码点集 `S_e` 是否支持实际 PPA 下游任务。当前优先级为：

1. 节点任务：对每个 cell/node 预测 area、power 或 timing 连续标签，只在对应 `has_*` 有效节点上计算损失和指标。
2. 关系任务：对有序 timing arc 预测 delay、slack、criticality；关系端点必须先映射到输入图节点，未映射关系不能进入监督。
3. 设计任务：作为补充，对整张设计预测 total power、WNS 或 TNS；不把设计级标量混同为节点/关系恢复。

关系结构恢复只作为可选辅助目标，不是 EDA 默认目标。只有当某个来源的关系端点覆盖和标签覆盖通过审计时，才允许打开
reconstruction loss；节点 PPA 和设计 PPA 任务默认使用 `G -> S_e -> y_task` 的任务损失。

## 数据集必须处理的问题（2026-10-23）

在进入正式节点/关系实验前，必须处理以下数据问题：

- **标签覆盖不均衡：** 5,772 个 pair 的 fine node area 覆盖 4,547,889/7,998,693 个节点，power 覆盖
  1,924,899 个，timing 覆盖 206,289 个；所有连续损失必须使用字段级 mask，不能把缺失值当零。
- **设计级零值语义：** `labels.json` 中 power 字段在所有来源都存在，但很多来源的零值是默认活动或无效结果；
  power 监督必须保留工具有效性和来源 metadata，不能只依据字段存在或数值非空。
- **关系端点不一致：** 非 TimingPredict 的大量 timing arc 端点不能映射到当前 `cell/net` 节点；未映射关系必须
  被排除，或先把输入图提升为 pin-level/经过验证的 cell-level aggregation，不能直接构造关系 target。
- **关系类型不完整：** 输入 G 有 `r_null/cell_to_net/net_to_cell`，fine relation 主要只有 `cell_to_net/timing_arc`；
  `net_to_cell` 缺失不能被当作负关系标签。
- **执行规模协议：** 图规模会影响 dense V1-C 的显存和 batch 组织，但不构成数据集正确性问题；是否使用
  整图、降低 batch、分块或稀疏实现属于执行配置，不得因此修改原始图或补造标签。
- **监督来源分层：** TimingPredict 只有 21 个 pair，area/WNS/TNS 设计级标签只在该来源存在；CircuitNet、EPFL、ITC99、
  OpenLane-local 主要适合 area/结构或 design power 子任务，不能合并为同一 timing 数据集。
- **数据划分：** 当前按 manifest 顺序的 80/20 split 只是 smoke 协议；正式结果必须按 design/source 去重后固定 train/valid/test，
  避免同源变体、重复网表或来源分布造成泄漏。

研究目标是验证受限关系族上的关系保持点集编码：固定维度点集 `S_e` 是否能够近似保留图信息，

## 已确认约束

编码器输出 `S` 应对节点排列保持等变，关系解码器应按相同排列变换。全关系批量计算的基本存储规模为 `O(n^2)`，迭代 `T` 次时至少需要报告 `O(T n^2)` 级别的点对计算。

## V0 基线实现（历史对照）

V0 按 `for-agent.txt` 的极简基线拆分为独立模块：`ENCS` 和 `ENCR` 负责 MLP 预编码，
每个演化层独立拥有 `PAIRATTN`、`ENCO`、`Gate` 和 `LayerNorm`，终态使用独立的
`SETATTN_out` 与 `PAIRATTN_out` 解码节点和有向关系。实现位置为 `code/v0/`，隔离测试位置为
`test/v0/`，不会复用旧版 `code/*.py` 的模型连接。

V0 当前使用连续节点向量和连续关系向量，因此节点类型数、关系类型数均不适用且不可数；
若后续接入离散图，必须重新声明节点类别、关系类别和显式 `r_null` 的编码方式。
V0 已通过 CUDA 前向、反向、padding mask、有限数值和排列等变性 smoke，并通过
`demo/demo_v0.py` 的独立前向 demo。原公式中的 `similar` 尚未指定具体形式，当前只保留可替换
接口；当前连续 V0 的训练主损失使用 masked MSE，余弦相似度保留为评估指标，不能视为训练目标。

V0 嵌入还原实验使用低秩连续关系族：节点特征经过固定源/目标线性映射生成有向全关系张量，
训练/验证 split 使用不同节点采样但共享关系生成规律。实验入口为
`script/train_v0_reconstruction.py`，数据位置为 `dataset/v0_reconstruction.py`，训练实现为
`code/v0/training.py`。该实验只验证 `G -> S_e -> G'` 的可训练闭环；低秩数据上的短时 smoke
不能替代独立随机关系容量边界、真实图数据或多种子实验。一次 50 epoch、256/64 张训练/验证图的
正式运行达到验证 MSE `3.4476e-02`，节点 MSE `9.5469e-03`，关系 MSE `2.4929e-02`；
该结果只对应当前低秩生成机制和单个随机种子。

真实数据实验入口为 `script/train_v0_real.py`，转换器为 `dataset/v0_real_molecule.py`。ZINC
使用 21 类节点、3 类真实键和 1 类显式 `r_null`，得到 4 类稠密关系；QM9 使用 5 类节点、
3 类真实键和 1 类显式 `r_null`，同样得到 4 类稠密关系。稠密 one-hot 节点/关系作为 V0 的
连续输入，padding 只由 `node_mask` 排除，不替代 `r_null`。当前已通过 ZINC 和 QM9 batch
读取 smoke，并完成一次 ZINC train/val 正式还原训练；该结果尚未包含官方 test split、多种子
或基线比较。

当前 V0 训练损失在 MSE 主项之外允许加入可导的关系相近度辅助项：
`L = L_node_mse + L_relation_mse + lambda_similarity * (1 - cosine(R', R_target))`。
关系准确率不参与反向传播，只作为离散评估指标。`lambda_similarity` 是实验参数，当前 smoke
使用 `0.1`，不能视为已确定的最终权重。训练进度按 5 秒时间间隔节流输出，epoch 汇总始终保留。

当前阶段定位为算法机制验证，不进行多随机种子实验，以节约实验时间。优先验证单种子下
`G -> S_e -> G'` 的真实图还原、关系相近度辅助损失是否有作用，以及官方 test split 上的
节点/关系离散还原指标；多种子和统计比较延后到算法机制确认之后。

演化轮数由 `layers` 控制。增加 `layers` 会增加独立的偏差计算与点集更新轮次，模型参数和
计算量都会增加；不同轮数必须重新训练，不能直接复用其他轮数的 checkpoint。当前下一项机制
实验采用 `layers=4`，与 `layers=2` 使用相同数据、损失和单种子配置进行比较。

单种子 ZINC train/val 对照中，加入 `lambda_similarity=0.1` 后，epoch 30 的关系 MSE 为
`6.9146e-03`，此前无辅助项结果为 `7.0287e-03`；节点 MSE 为 `2.8112e-05`，与此前
`2.7560e-05` 同量级。总验证损失包含辅助项，不能直接与无辅助项的总 MSE 比较；该结果只
支持“关系相近度可能改善关系数值还原”的初步假设，仍需 test split 验证。

已使用 `runs/v0_real/zinc_similarity_best.pt` 在 ZINC 官方 test split 上完成离散关系评估：
节点 accuracy `0.999955`，全部有序关系 accuracy `0.977471`，真实边类别 accuracy
`0.819735`，`r_null` accuracy `0.993029`，关系 macro-F1 `0.898420`，边存在性
macro-F1 `0.927660`。这说明 V0 能从 `S_e` 恢复大部分关系，尤其能区分无边与真实边；
真实边具体类别仍有约 18% 的错误，因此结论应表述为关系近似恢复，而不是完全恢复。

## 第一版实现规格

当前组件规格：缩放点积 `ENCS`、单头 `SETATTN`、演化 `PAIRATTN`、独立终态
`recovery_pair`、`ENCR` 关系对齐和
三分支条件 `ENCO`、逐维 Sigmoid 软门控和残差迭代更新。`ENCR` 给出
`r_tilde = r + ENCR(r)`，随后 `ENCO` 使用
`u = MLP(concat(p W_P, r_tilde W_R, (p U_P) * (r_tilde U_R)))`；输入关系是条件，
不再以 `r - p` 将当前点对状态回拉到输入图。完整公式、张量形状、mask 语义、损失及验证项在
`具体设计.txt` 中维护。

该规格已完成模块级、完整前向和训练闭环 smoke，实现位于 `code/encs.py`、`code/setattn.py`、`code/pairattn.py`、`code/evolution.py`、`code/model.py`，正式短时入口为 `script/run_autoencoder_smoke.py`。这仍不等同于 `project/` 正式版本；`beta`、`epsilon`、迭代步数、各宽度和损失权重均须通过后续训练实验确定。

连续合成训练闭环已实现：`dataset/synthetic_relations.py` 生成共享关系规律的训练/验证图，`code/training.py` 提供 masked MSE、训练/验证 epoch 与 checkpoint，`script/train_synthetic.py` 提供可配置训练入口。该数据仅验证工程路径，不能替代真实图数据集上的结果。

`script/evaluate_synthetic.py` 已对最佳 checkpoint 做独立合成图评估，并同时报告零预测基线的节点/关系 MAE 与 RMSE。当前结果支持“在同一低维关系分布上存在非平凡重构”，但不替代与 GAE、GINE、Graphormer、GraphGPS、GRIT 的同预算比较。

真实分子数据已采集：ZINC subset 的节点/真实边类型数为 `21/3`，QM9 为 `5/3`；加入显式 `r_null` 后二者均为 4 类关系。该段历史记录描述 V0 接入前的状态；当前 V1 已支持真实 one-hot 图 batch、MSE 训练和离散关系评估，图级任务头仍未实现。

轻量下游验证现已加入连续合成节点/边任务：输入节点和关系均不可数，节点和有向边目标均为
2 类可数标签。主任务的节点标签来自入射关系摘要，边标签由源/目标节点摘要组合，因而与
点集节点状态和有序点对读出相匹配；`two_hop` 高秩目标保留为容量压力组。`S_e` 经独立
终态 `recovery_pair` 读出节点和边 logits，演化内部的 `PAIRATTN` 不复用于最终关系恢复。
该实验验证点集嵌入可服务于
与节点集合和有序点对集合对齐的任务，但不替代真实分子数据上的离散分类和下游结果。

当前轻量对照已验证 `G -> S_e -> {节点读出, 有序点对读出}` 这条训练链路可学习：在同一
合成数据、split、模型宽度和训练预算下，`L=0` 基本停留在类别先验，而 `L=2` 的测试节点/边
准确率达到 `0.825/0.740`，超过多数类基线 `0.525/0.545`。该结果首先说明链路可训练，
不单独证明模型泛化；学习效果依赖数据集是否完整提供关系条件、目标生成机制是否与点集表示
匹配，以及训练/验证/测试 split 是否保持一致。

## 已验证的 ENCS 候选

`code/encs.py` 实现了给定的缩放点积 `AttentionSmooth`：先计算 `S_bar = MLP(X)`，再用 `softmax(S_bar @ S_bar^T / sqrt(d)) @ S_bar` 得到低频分量，最后对高频残差和 `epsilon * noise` 做逐节点 `L2` 归一化并乘以 `beta`。输入和输出均为 `[B, v, d]`；实现支持外部传入噪声，以便复现实验和检查同步排列下的逐样本等变性。

随机噪声在固定样本下需要随节点排列同步，普通独立重采样只能保证分布意义上的等变性；`beta`、`epsilon` 和 MLP 结构仍需后续审核。

## 下游任务统一视角

当前框架将下游任务表示为：

```text
G(X,R) -> S_e -> G'(X',R') -> y_graph
```

目标图预测首先由 `S_e` 解码得到 `X'` 和 `R'`：节点级任务评估 `X'`，关系级任务评估 `R'`，
图级任务再对 `G'=(X',R')` 或 `S_e` 执行置换不变聚合。节点/关系预测不是脱离图恢复的独立
分类任务，而是目标图 `G'` 的组成部分；图级任务可以不逐项精确重构全部关系，但它所需的
局部结构和全局统计量必须先保存在 `S_e` 或 `G'` 中。

状态说明：上方 V1 smoke 描述是历史阶段记录；随后已完成正式 ZINC 训练和 test 评估，当前
主线状态以本段和 `具体设计.txt` 的 V1 规格为准。

## V1-C 自包含实现状态

V1-C 位于 `code/v1_c/`，模型入口为 `v1_c.V1CModel`，测试入口为 `test/test_v1_c_isolation.py`。
它保持当前 V1 的计算行为：V0 风格的 ENCS、ENCR、SETATTN、PAIRATTN、ENCO、Gate、逐层
EvolutionLayer 和独立 Decoder，并在每层演化后使用 AdaptiveNoiseFilter 注入自适应噪声。

V1-C 将这些组件全部复制到自身包内，并改用相对导入；它不从 `code/v0/` 或 `code/v1/` 导入
运行时代码。V1-C smoke 已验证本地导入、前向输出形状、padding 节点清零、有限损失和反向
传播。该 smoke 只证明工程隔离和接口可运行，不代表 V1-C 已完成 CUDA、真实数据训练、test
评估或主线版本认证。当前主线仍为 V1，V1-C 仍是待进一步验证的候选实现。
