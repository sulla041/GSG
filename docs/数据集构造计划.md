## 图对优先原则

正式训练样本必须是一个可审计的有向图对：

```text
pair = {input_graph: G, output_graph: G', node_map, relation_map, conditions, provenance}
```

`G` 是模型可见输入，`G'` 是同一设计、同一条件下由 EDA 阶段变换得到的输出图。监督值只能作为 `G'` 的节点、关系或图级属性保存，不能用“输入图加一个脱离图结构的 labels 文件”替代输出图。

## 论文正文版数据集描述

意涵，论文可采用以下最新版本描述数据集：

> 本研究基于 CircuitNet 3.0 RTL 设计集，使用 Nangate45 工艺库构造可审计的多阶段电路图数据集。数据集首先通过确定性的 Yosys 综合与逻辑映射生成 mapped netlist，随后使用统一 OpenROAD 流程完成 floorplan、placement、CTS、global routing、detailed routing、寄生提取以及内置 STA/power 分析。原始 RTL 共 5,999 个，其中 5,965 个完成综合并进入物理实现，34 个在综合阶段失败；在物理阶段，5,965 个请求全部完成处理，其中 4,468 个生成有效物理产物，1,497 个保留为失败记录。
>
> 每个正式样本被定义为有向图变换 `G -> G'`，并同时保存节点映射、关系映射、工艺与时序条件以及来源 provenance。数据集包含 `G_logic_pre_map`、`G_mapped_cellpin`、`G_place`、`G_route` 和 `G_rc` 五类图视图。`G_mapped_cellpin -> G_place` 阶段生成 4,468 个候选 pair，其中 4,318 个为严格 pair、150 个存在映射缺口；后续 route/RC 阶段生成 4,468 个候选记录，其中 3,719 个为严格 pair、749 个为 partial。partial 样本保留未匹配实体、失败原因和 valid mask，不计入严格测试集。
>
> 为避免信息泄漏，数据集分为基础网表轨道和寄生增强轨道。基础网表轨道使用逻辑、library、cell/pin、net 和 placement 信息，服务于面积、漏电、逻辑统计、cell arc、placement 以及 pre-route 预测；寄生增强轨道使用 route segment、via、layer、R、ground-C、coupling-C 和端点映射，服务于 RC、net delay、pin timing 和 post-route QoR 预测。所有任务按 `design_id` 划分训练、验证和测试集合，使同一设计的不同阶段与不同轨道不会跨集合泄漏。
>
> 数据集定义九个正式下游任务：A1、S1、D1、D2、D3、R1、P0、P1 和 P2。最终任务 manifest 覆盖 5,965 个 design、53,685 条任务记录；其中 `pair_ready`、`source_pending` 和 `target_pending` 分别表示可直接监督、来源未登记和目标未对齐。只有同时具备输入图、输出图、映射文件、条件、来源和有效目标的记录才进入普通监督训练，partial 记录仅在使用 mask-aware loss 时进入扩展训练。

正式 pair 必须同时满足：

1. `input_graph` 和 `output_graph` 都有稳定 schema、节点类型数、关系类型数及其可数性声明。
2. 两张图共享 `design_id/top/clock/library_hash/flow_hash/stage/corner/mode`，并保留 `source_hash`。
3. 节点和关系通过 `node_map`、`relation_map` 对齐；新增的物理节点允许只出现在 `G'`，但必须标记 `added=true`，不能静默丢弃。
4. 输出图中的每个数值属性都保存 `value/unit/valid_mask/source_artifact/source_hash/tool_version`。
5. 输入图中不得读取输出阶段产生的标签、未来物理坐标、SPEF 数值或由目标反推的统计量。

没有 `G'` 的 CircuitNet 原生 timing/power 记录保留为 `external_supervision`，不计入严格的图对数据集规模。

## 样本单位与图视图

一个样本对应一个顶层设计、一个时钟约束、一个工艺库版本和一个实现阶段。样本通过 `design_id`、`top`、`clock`、`library_hash`、`flow_hash`、`stage` 和 `corner` 关联。

| 图视图 | 节点 | 关系 | 主要任务 |
| --- | --- | --- | --- |
| `G_logic_pre_map` | 非正式保留视图 | 不进入正式任务 | 已排除 |
| `G_mapped_cellpin` | design、cell instance、library master、pin、port、net、clock、constraint | cell-pin、pin-net、driver-sink、cell timing arc、层级与时钟连接 | A1、S1、D1、D3 |
| `G_place` | `G_mapped_cellpin` 节点加 die、row、site、placement instance | 逻辑连接加 placement 归属、row 邻接 | P0、P1 |
| `G_gcell` | GCell bin | 邻接、水平跨越、垂直跨越、net 覆盖 | P1 |
| `G_route` | cell、pin、net、route segment、via、layer、track、GCell、die、row、site | 逻辑、placement、route、via、layer、track、拥塞连接 | P1、R1 |
| `G_rc` | `G_route` 节点加 RC node、RC segment、ground capacitor、coupling capacitor | 电阻、地电容、耦合电容、pin/terminal 映射 | D2、D3、P2 |

## 两条任务输入轨道

意涵，所有下游任务按输入信息量分为两条轨道；两条轨道共享 `design_id`、工艺条件和阶段键，但不共享会造成目标泄漏的输入属性。

| 轨道 | 输入图 | 输入信息 | 适用任务 | 输出形式 |
| --- | --- | --- | --- | --- |
| 基础网表轨道 | `G_mapped_cellpin`、`G_place` | cell、pin、net、library master、逻辑连接、约束、布局坐标和状态；不读取未来 route/SPEF 数值 | A1、S1、D1、P0、P1，以及不依赖真实寄生的预估任务 | 同拓扑图增加节点/关系/图级目标，或下一阶段 `G_place/G_gcell/G_route` |
| 寄生增强轨道 | `G_route`、`G_rc` | route segment、via、layer、net 几何、RC node、R、ground-C、coupling-C、driver/sink 和端点映射 | R1、D2、D3、P2，以及明确要求后布线物理信息的任务 | `G_route -> G_rc`，或同一 `G_rc` 增加 timing/QoR 目标 |

基础网表轨道负责“正常网表能推断什么”，寄生增强轨道负责“加入布线和寄生后还能推断什么”。例如 D2/D3/P2 的后布线目标使用 `G_rc` 输入；如果只使用正常网表，则应单独命名为 pre-route 预测任务，不能与后布线真实目标混用。R1 是 route 到 RC 的图构造任务，不把最终 R/C 数值同时作为 R1 的输入特征。

## 正式图对层级

| Pair ID | 输入图 `G` | 输出图 `G'` | 对应关系 | 进入主数据集 |
| --- | --- | --- | --- | --- |
| `pair_logic_to_map` | `G_logic_pre_map` | `G_mapped_cellpin` | RTL 逻辑节点到综合 cell/pin/net 的显式 mapping；允许一对多、多对一 | 只有 mapping 完整时 |
| `pair_map_to_place` | `G_mapped_cellpin` | `G_place` | cell/pin/net 保持主键，新增 die/row/site/placement 节点标记 added | 是 |
| `pair_place_to_route` | `G_place` | `G_route` | 原有节点保持 ID，新增 segment/via/layer/track/GCell 节点标记 added | 是 |
| `pair_route_to_rc` | `G_route` | `G_rc` | route 节点保持 ID，新增 RC node/capacitor 节点标记 added | 是 |
| `pair_map_to_rc` | `G_mapped_cellpin` | `G_rc` | 通过中间阶段 manifest 串联，不直接猜测跨阶段 ID | 只有链路完整时 |

当前主线优先构造 `pair_map_to_place`、`pair_place_to_route` 和 `pair_route_to_rc`。新版 `pair_place_to_route` 会复制 `G_place` 并追加真实 DEF segment/via/layer 节点；新版 `pair_route_to_rc` 会输出 RC graph、net mapping、endpoint mapping 和未匹配审计。GCell 仍需从 global-route ODB 单独补齐，不能用 DEF segment 冒充 GCell。它们共享同一 mapped netlist 和同一次 OpenROAD flow，节点对应关系比 RTL 到综合后的关系更稳定。`pair_logic_to_map` 单独作为需要综合映射审计的扩展任务。物理队列使用 tmux socket `dac2027-phys` 的会话 `dac2027-circuitnet3-openroad`，日志为 `/data/yiyh/dac2027/runs/dac2027-circuitnet3-openroad-20261031.log`。

统一流水线由 `script/run_circuitnet3_pair_pipeline.py` 协调：只消费 `physical_ready/cached`，按 `map-place -> route/RC -> pair registry -> task pairs` 依赖提交，并使用 `pipeline.lock` 保证单实例。新版 route builder 从 `6_final.def` 解析 segment/via/layer，从 `6_final.spef` 解析 `*CONN`、R、ground-C、coupling-C，并把未匹配的后插入物理 pin/寄生节点写入 mapping audit。当前允许 partial usable 样本进入覆盖统计，未匹配端点通过 `valid_mask` 保留；如果缺少 `G_place`，则使用同设计 mapped netlist 生成 `placement_complete=false` 的 partial 输入图；只有 endpoint、net、placement 和条件均完整时才登记严格 `route_rc_pair_ready`。

### 多核流水线策略

意涵，当前机器有 128 个逻辑 CPU 和约 503 GiB 内存。OpenROAD 已切换为 `3 × 32` 的 design 级并行，总计约 96 个线程；map-place、route/RC 可以把不同 design 分发给 worker，但不能让多个 worker 直接写同一个 manifest；task registry 是轻量索引阶段，保持单 worker。评价标准包括 physical 成功率、单 design 时间、RSS、manifest 完整性和 partial 比例。

map-place 和 route/RC builder 已支持增量复用：完整 pair 目录直接沿用旧记录，只有新增或不完整 design 才重新构造；这样多核 worker 的写入范围保持在独立 design 目录，manifest 仍由 supervisor 统一提交。

### 检查方法索引

意涵，运行检查按以下顺序执行：先读取 physical/map/route/task 四个 manifest 的 `completed`、`requested`、`status_counts` 和修改时间；再统计每个 design 的 `physical_manifest.json`；构造期间检查 tmux pane 和实际子进程，完成后确认两个项目 socket 均无 server 且无构造进程；最后从 latest 快照核对四阶段计数。`pending` 重试量与新增 ready 量必须分开统计，避免把失败重试误认为数据集增长。

现有后端 `G_postroute_cellpin` 使用 8 类节点和 14 类关系；`G_rc` 在此基础上表达寄生 R、ground C 和 coupling C。关系特征保存方向、端口角色、cell master、pin 功能、逻辑极性、时钟域、坐标、层、宽度、长度、R、C、corner 与阶段标识。

### 任务运行顺序

每个设计按以下顺序运行，后一任务只接收前一阶段已验收的图和 mapping：

```text
Yosys mapped netlist
  -> G_mapped_cellpin
  -> OpenROAD floorplan/place
  -> G_place                 -> P0
  -> OpenROAD CTS/global route/detailed route
  -> G_gcell + G_route       -> P1
  -> OpenRCX/SPEF
  -> G_rc                    -> R1, D2, D3, P2
  -> OpenROAD built-in STA   -> D1, D2, D3, P2 attributes
```

A1/S1 可以在 `G_mapped_cellpin` 上作为同拓扑输出图先生成。任何任务如果只能得到独立 label 表，先保存为 `label_artifact`，不能登记为正式 `G -> G'` pair。

### 匹配验收

每条 pair 在 registry 中必须同时记录：`input_graph`、`output_graph`、`node_map`、`relation_map`、`conditions`、`source_artifact` 和 `source_hash`。验收至少检查：

1. 输入图与输出图的样本键一致，且 stage 明确表示输入/输出阶段。
2. 保持的实体通过语义主键一一对应；新增实体有来源 artifact key。
3. 输出属性的节点/关系 ID 都能在 `G'` 找到，缺失值使用 `valid_mask=false`，不填零。
4. 任务输入不读取该任务的输出属性；报告、ODB、DEF、SPEF 和 Liberty 来源均可回溯。

## OpenROAD 内置 STA/RCX 构造产物

每个 timing 会话由 OpenROAD 读取 LEF、Liberty、mapped/final netlist、SDC 和 SPEF，执行 max/min 分析并导出功耗；独立 OpenSTA 只用于已有工件的补充复核，不作为全量主链路。

| 输出 | 任务 |
| --- | --- |
| cell timing edge 及 delay/check 属性 | D1 |
| wire timing edge 及 delay | D2 |
| pin arrival、slack、slew 的 max/min rise/fall 值 | D3 |
| `report_wns`、`report_tns`、worst slack path、critical arrival、`report_power` | P2 |

统一时序条件字段为 `analysis_type`、`corner`、`mode`、`clock_name`、`clock_period`、`library_hash`、`sdc_hash`、`spef_hash`、`stage` 和 `tool_version`。

## 全量构造流程

1. 解析 CircuitNet 3.0 的 RTL 文件、top 和 clock，生成确定性设计清单。
2. 使用 Yosys 与 Nangate45 生成 `G_logic_pre_map`、mapped netlist 和 `G_mapped_cellpin`；保存综合 mapping artifact。
3. 使用 OpenROAD 统一生成 floorplan、placement、CTS、global route、detailed route、final DEF/ODB/SPEF，并在同一 flow 中执行内置 STA/RCX。
4. 从每个阶段产物构造 `G_place`、`G_gcell`、`G_route` 和 `G_rc`，保留前一阶段节点主键并登记新增节点。
5. 将每相邻阶段封装成独立 pair，监督值写入 `G'` 的节点/关系/图属性；不再把 labels 文件作为唯一输出。
6. 写入 pair registry，执行图结构、节点/关系映射、单位、键关联、覆盖率和 source hash 校验。

## 2026-11-06：CC-Tensor v3 极速紧凑离散因果张量化重构需求

意涵，基于 2026-11-05 在长程深层演化（$T=64$, 1000步）下取得的史诗级突破（因果拓扑排序相关性 $r=0.9466$、全局决定系数 $R^2_{\text{pool}}=0.8593$），为彻底解决现有张量组织中 GPU 重复在线查表/统计与显存带宽浪费的问题，现确立新一代**紧凑因果电路张量标准（CC-Tensor v3）**构造需求，以支持全量样本 100% 常驻 GPU 显存并加速训练吞吐。

### 1. 现有 v2 张量瓶颈剖析（第一性原理）
- **高维稀疏浮点冗余**：旧版张量保存展开后的 76 维节点与 30 维关系 float32 稀疏 One-Hot，95% 以上存储为 `0.0f`，单图体积 0.6 MB ~ 2.5 MB，挤占磁盘与总线带宽；
- **GPU 在线前向重复算力开销**：在 $T=64$ 高频演化循环中，模型每一步前向都必须在 GPU 上重复执行 `argmax` 提取类别 ID、预设查表（LUT）解析门类型与驱动倍率，并通过 `scatter_add` 重新统计全图节点出入度，引入了大量无谓的 CUDA 显存同步碎片；
- **扩展性受限**：稀疏显存占用导致最大节点数被动限制在 2048 节点内。

### 2. CC-Tensor v3 详细张量数据结构规范

每个样本保存为一个紧凑 PyTorch `.pt` 字典，包含四大解耦模块：

```python
sample = {
    # 1. 节点 6 大平衡通道解耦属性 (严格无层级作弊，单节点仅 17 字节)
    "node_kind_id": torch.Tensor,       # [N], torch.uint8, 取值 0..9 (实体微观类别)
    "node_base_id": torch.Tensor,       # [N], torch.uint8, 取值 0..28 (解耦门基础逻辑类型)
    "node_drive_val": torch.Tensor,     # [N], torch.float32, 驱动强度 log2(drive)/5.0
    "node_pin_id": torch.Tensor,        # [N], torch.uint8, 取值 0..18 (引脚端口类型)
    "node_log_out_deg": torch.Tensor,   # [N], torch.float32, 负载电容 log(1+FanOut)
    "node_log_in_deg": torch.Tensor,    # [N], torch.float32, 扇入争夺 log(1+FanIn)
    "source_anchor_mask": torch.Tensor, # [N], torch.bool, 入度为 0 的 Primary Input / 时钟源头掩码

    # 2. 拓扑关系与因果单向边表 (单边仅 9 字节)
    "edge_index": torch.Tensor,         # [2, E], torch.int64 (纯真正向因果有向边)
    "edge_type_id": torch.Tensor,       # [E], torch.uint8, 取值 0..13 (14 种微观拓扑关系类别 ID)

    # 3. 监督真值与有效掩码
    "arrival_time": torch.Tensor,       # [N], torch.float32, 节点真实到达时间 (ns)
    "target_mask": torch.Tensor,        # [N], torch.bool, 时序真值有效监督掩码

    # 4. 全局设计元数据与时序统计
    "meta": {
        "design_id": str,
        "num_nodes": int,
        "num_edges": int,
        "max_depth": int,               # 纯用于事后审计，严禁作为模型输入
        "num_targets": int,
        "arrival_stats": {
            "min": float, "max": float, "mean": float, "std": float
        },
        "has_loop": bool                # 严格无环 DAG 验证
    }
}
```

### 3. 关系物理阻抗直连机制
- 边表仅保存 `edge_type_id`，不冗余存储实数阻抗；
- 模型内部前向时，直接通过源宿索引从节点收集阻抗：
  $$\text{rel\_num\_in} = [\text{node\_log\_out\_deg}[\text{src}], \text{node\_log\_in\_deg}[\text{dst}]] \in \mathbb{R}^{E \times 2}$$
  实现显存与存储的双重零浪费。

### 4. 收益指标与构建执行准则
- **压缩比**：单图体积由 ~1.23 MB 降至 20~80 KB（压缩率 > 93%），308 全量子集常驻显存仅需 ~33 MB；
- **吞吐加速**：前向传播彻底消除 `argmax` 与动态度数统计，单 step 预估加速 3~4 倍；
- **构建规范**：
  1. 并行转换脚本必须严格遵循系统剩余内存 $\le 50\%$ 的内存红线；
  2. 输出目录统一为 `/data/yiyh/dac2027/dataset/circuit/circuitnet3_v3_03_compact_tensors/`；
  3. 必须通过全量数值无损断言（新旧张量解耦后的数值和目标对齐误差绝对为 0）方可接入正式训练。

### 3. 元数据与数据泄漏边界

意涵，`meta` 至少包含 `design_id`、`task`、`track`、`num_nodes`、`num_edges`、`num_targets`、`max_depth`、`has_loop` 和 arrival 统计。`max_depth` 只用于审计，严禁拼接到节点特征；扩展张量中不存在 `logic_level` 字段。关系阻抗应由 `edge_index` 的 source/destination 索引读取节点度数字段，不从输出图反推输入特征。

### 4. 训练读取与 mask 规则

意涵，节点级监督必须使用 `node_target_mask`，不能把缺失目标的默认零值当作真值；图级监督必须使用 `graph_target_mask`。D1 timing 训练优先使用 `arrival_time[target_mask]`，D2 需要使用关系级有效标签时，应回到 `node_targets`/关系目标字段对应的 mask，不得把所有 RC 图边视为有标签。
