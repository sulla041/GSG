# 行为准则

电路 PPA 数据必须先经过固定网表阶段，再进入 OpenSTA 标签阶段；只有两个阶段都成功的图才能计入 accepted graph 数量。netlist 失败和 label 失败必须分开记录。

电路输入必须明确 Sky130 兼容边界：未解析的 vendor IP、FPGA primitive、black-box memory/PLL、缺失 include/macro 和仿真专用模块不能被伪装成有效 PPA 标签。

当前 Cora 下游任务中，每个缺边掩码都视为独立输入图 G_k；已观察边只作为输入上下文，
关系损失只作用于隐藏真实边和等量真实非边查询，不把完整输入关系矩阵当作恢复目标。
下游实验必须同时报告节点指标、关系查询 accuracy、edge precision/recall/F1 和 hidden-edge recall；
稠密关系 accuracy 不能单独代表缺边预测能力。

本项目遵循 `for-agent.txt` 的工作约束；该文件是任务输入，不在此修改。用户称呼为意涵，
沟通保持积极、清晰并促进思考。

- 先在 `test` 验证，再提升到 `code`、`doc`、`script`，通过 `demo` 后才进入 `project`。
- 任何新增算法细节必须先记录为待审核假设，不把假设写成已确认结论。
- 每个 Python 文件少于 150 行，关键函数使用中文注释，模块保持单一职责。
- 图任务先记录节点种类数、边/关系种类数，以及类型是否可数。
- 训练和实验提供进度输出，并保留设备、随机种子和配置记录。
- 训练循环默认每 5 秒最多输出一行进度，epoch 汇总保留；长实验必须保留可复制命令和完整日志。
- 短时 smoke 由代理执行；数据集收集、网表生成、标签流水线和用户要求自动运行的长时间模型训练，均放入独立 tmux 会话；模型任务按单任务顺序运行，避免 CUDA 并发争用。
- 正式版本必须支持 CUDA，并区分稠密关系与稀疏关系的语义。
- 图任务先明确节点/关系类型数及其是否可数；离散图显式保留 `r_null`，不能用 padding mask 代替关系类别。
- V2 dense multi-hop topology 任务必须使用 topology-only 节点输入，不加入 electrical/process features；每个有序关系状态必须
  有独立的向量状态，`r(i,j)` 与 `r(j,i)` 的 forward/reverse relation vector 不得合并。`PAIRATTN` 只读取节点对，
  relation vector 由 `ENCR` 编码后再与 pair state 在 relation head 中融合。
- Dense multi-hop 标签可使用 topology-only 的 all-pair `reachable` 和 masked `min_hop`；不得把 OpenSTA delay、slack、
  criticality 反推到 dense 输入。reachability 结果必须同时报告 balanced metrics 或 per-hop metrics，不能只报告整体 accuracy。
- 同一物理 netlist 可以为不同任务提供不同图视图：mapped PPA 使用 cell/net bit/I/O/constant
  图，pin timing 使用 cell-pin/I/O 图；任务标签必须与该视图的节点和关系一一对齐，不能跨视图
  直接复用端点。
- DAC-EDA 主预测任务固定登记为八个独立单模型任务：mapped-cell area、internal/switching/leakage/total
  power、pin `CELL_ARC` 的 rise/fall/worst delay；graph area 和 graph total power 由对应节点预测求和，
  只作聚合评估，不与节点任务合并训练。`NET_ARC` 只作拓扑，recovery 指标只作辅助证据。
- 节点 area/internal/leakage 等局部 PPA 只能作为控制实验，不能单独证明电路关系建模有效；graph area/total power 若由节点预测求和，不得写成独立图级训练任务。
- 电路表征主任务必须使用完整输入图 `G=(X,R)`；不得通过隐藏边、删除关系或人为破坏输入来制造图敏感标签。图敏感性应来自任务本身对路径、方向、多跳传播、综合结构或功能的依赖。
- DAC 投稿优先任务为完整图级 QoR、path-level timing、Yosys/ABC synthesis candidate ranking，以及 Yosys equivalence/formal 驱动的功能/结构任务。MLP 保留为只用节点属性的下界。
- Yosys/ABC + OpenSTA 结果必须标记为 synthesis-level；只有经过 OpenROAD placement/CTS/routing、OpenRCX SPEF extraction 和 post-route OpenSTA 的结果才可标记为 physical-level PPA，不把 mapped cell area 叫作完整 die area。
- power 标签必须登记 activity 来源、VCD/SAIF 或 vectorless 假设、Liberty/corner/frequency；没有这些 metadata 时只能称为 default-activity estimate，不能称为完整工作负载功耗。
- DAC predictor 是当前新算法主线；Agent Phase 2 的 T1 timing closure、T2 area compression、
  T3 power compression、T4 multi-objective PPA 只是 predictor 之上的子实验，必须经过真实
  EDA flow 和等价检查，不能替代 predictor 的主要评估。
- DAC 连续正值 PPA 回归统一采用尺度稳定协议：训练前在有效标签上进行 log-space 标准化，使用 masked Huber
  loss；预测后还原到原始物理单位，再计算 MSE、RMSE、MAE 和 MAPE。零值 power 只在有效 mask 下参与绝对误差，
  不进入 MAPE 分母；分类、结构恢复和非正值任务不套用该协议。
- DAC 主表必须区分任务粒度：节点 area/power 按有效节点报告，pin delay 按有效 `CELL_ARC` relation 报告；MAPE
  按有效 prediction 计算，主表优先报告设计级 macro `mean ± std`，并同时保留 valid design/relation 数量和 raw-space
  MSE/RMSE。单 seed 的 `± std` 只表示测试设计分布，不称为置信区间。
- DAC 推理成本主指标是单个 design 的完整 model-forward 时间，优先报告 `ms/design`；节点、dense pair 和有效 relation
  的摊销时间只用于按图规模归一化和横向比较，不能解释为单个节点或 relation 的独立执行时间。规模实验必须按节点数分桶，
  同时记录时间均值/中位数、离散程度和 peak GPU memory。
- 推理成本必须保存每个 design 的 `(N, t_design)` 配对，至少拟合
  `t_design(N)=alpha+beta*N+gamma*N^2` 并报告拟合误差/R²；dense V1-C/global PAIRATTN 的 `N^2` 项是主要解释变量。
  `E_valid` 只能作为 delay relation 任务的辅助变量，不能替代节点数规模关系。
- 旧 raw-scale baseline 只作为历史对照，不与 log-space 新实验的训练 loss 直接比较；新实验必须在 config/checkpoint 中登记
  target transform、epsilon、loss、MAPE zero policy 和 feature profile。
- 分层 N² 方案目前只是待审核探索方向，不得自动替换 V1-C 主线：cluster 划分必须只使用拓扑和合法输入特征，不能读取
  delay、power 或其他 target-derived 字段；现有 `labels_ppa_cluster_v2` 中的 `y_power` 不能作为模型输入。
- 分层 delay 实验必须保持 relation-level `CELL_ARC` 目标和 global PAIRATTN 语义；局部 pair、cluster pair 和跨 cluster
  relation readout 的边界、mask、复杂度和显存峰值必须先通过独立 smoke，再决定是否进入 `code/v1_c/`。
- 当前 dense V1-C 的正式可接受执行边界为 `max_nodes=2048`；`max_nodes=4096` 已在 A100 40GB 的 timing backward
  阶段发生 CUDA OOM，不得继续作为默认实验边界。超大图必须等待分层/chunked/sparse 方案通过显存 smoke 后再纳入。
- 当前 DAC predictor 的主要改进优先级是重新选择图敏感下游任务并完成两级 EDA 标签闭环，不是继续堆叠普通节点 PPA 训练轮数；activity、频率、slew、load/capacitance 和逻辑状态是 switching/power 或 timing 增强任务的可选输入字段，必须有可靠来源和 metadata，不能从标签或拓扑伪造。
- GSG 内部还保留合成、ZINC/QM9、Cora 和 SKY130 pair 任务，但不能与 DAC-EDA 任务混称。
- “支持”必须区分数据读取、smoke 闭环和正式泛化结果；DAC predictor 的每个单任务必须分别报告 checkpoint、
  split、mask、test 指标和执行边界，不得用一个任务结果代表其他任务。
- 根目录仅维护行为准则、工程结构、试验记录和算法描述等约定文档；用户维护的设计输入文件保持只读。
- 任何新增算法细节必须先作为实验参数或待审核假设记录，不能擅自固化为最终结论。
- 主线版本必须明确标记；每获得一个可接受的新实验结果，就建立新的版本记录，保留旧版本代码、配置、checkpoint 和结果，不覆盖历史版本。
- 统一实验输入目录为 `dataset/paired_graphs/` 时，必须保留 `input/netlist.json`、可选 `input/netlist.v`、`target/labels.json`、`target/fine/nodes.json`、`target/fine/relations.json` 和 `provenance.json`；缺少必要文件的 pair 不得进入训练。
- 电路 G 的节点类型为 `cell/net`，关系类型为 `r_null/cell_to_net/net_to_cell`，均为可数离散类型；G' 的 PPA 节点/关系标签是连续值并带有效性字段，不能把缺失值伪装成零。
- DAC mapped-v2 节点类型为 `standard_cell/net_bit/primary_input/primary_output/const` 五类可数类型，关系为
  `r_null/drive_to_net/net_to_load` 三类可数类型；pin timing-v1 节点类型为 `cell_pin/primary_input/primary_output/primary_inout`
  四类可数类型，关系为 `r_null/cell_arc/net_arc` 三类可数类型。两种视图的新增输入字段必须保持各自端点和 mask 对齐。
- 统一 pair 目录的 source manifest 是正式计数依据；外部 CSV 或未经本地 Yosys/OpenSTA 验证的标签只能作为辅助 metadata。
- `hub/` 明确表示 GitHub 仓库目录；涉及登录、拉取、提交、推送或其他远程仓库操作，必须获得明确授权。

状态：有效；本文件与 `for-agent.txt` 对齐，若约束变化需同步更新。
