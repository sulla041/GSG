## 正式样本目录

正式数据集使用图对目录，而不是输入图和标签的松散并列目录：

```text
pair_root/<pair_id>/
  input/graph.json
  output/graph.json
  mapping/node_map.json
  mapping/relation_map.json
  conditions.json
  provenance.json
```

`pair_id` 由 `design_id`、输入 stage、输出 stage、corner、mode、library_hash 和 flow_hash 决定。`output/graph.json` 内嵌目标属性，原始 ODB/DEF/SPEF/report 通过 `provenance.json` 回溯。

## 数据流

```text
CircuitNet RTL / local design
  -> Yosys: pre-map JSON, mapped netlist, G_logic_pre_map, G_mapped_cellpin
  -> OpenROAD: floorplan, placement, CTS, GCell, route, DEF, ODB, SPEF
  -> graph extraction: G_place, G_gcell, G_route, G_rc
  -> OpenRCX + OpenROAD built-in STA/power: RC, cell arc, net delay, pin timing, setup/hold and power metrics
  -> pair builder: G -> G', node/relation mapping, output attributes
  -> registry manifest: pair, graph, mapping, condition, source hash
```

## 下游任务支持统计

意涵，当前工程定义 9 个正式下游任务：A1、S1、D1、D2、D3、R1、P0、P1、P2。500 子集 9 个任务均已登记；A2 已明确排除，不再进入任务清单。D2 使用 relation-level `net_timing_target`，必须依据 valid mask 使用。

意涵，D1 的训练默认使用 `circuitnet3_v3_03_task_tensors_v2`，而不是旧的 v1。v2 通过 Nangate45 Liberty 校准引脚方向，恢复 `net -> input_pin -> cell -> output_pin -> net` 的信号流，删除 DFS 检出的反馈回边，并增加归一化 logic level；旧 v1 仅保留作回归对照。

意涵，旧扩展版寄生任务的 783 条记录只表示图结构已登记，不表示具备有效监督，因为抽查结果为 `node_target_mask=0` 且 `graph_target_mask=False`。新的 `expanded_parasitic` 轨道通过 OpenROAD/SPEF 重新写入 D2/D3/P2 真值，R1 使用 route-to-RC 图变换本身作为结构监督；训练时仍必须按任务使用 edge、node 或 graph mask。

意涵，完整流水线已经完成“physical -> map-place -> route/RC -> registry -> task pairs”提交；使用阶段直接读取 task manifest 和阶段 pair manifest，构造阶段的 tmux 会话已清理，所有路径和字段以 `工具指南.md` 的使用说明为准。

## 固定 IO placement 重跑轨道

意涵，本轨道只服务 placement/P0，不修改 `circuitnet3_nangate45_physical_v1`、`circuitnet3_map_place_pairs_v1`、timing、RC、power 或 CC-Tensor 目录。输入仍来自既有 `circuitnet3_nangate45_synth_v1` 的 mapped 网表，输出单独写入 `circuitnet3_nangate45_fixed_io_placement_v1/<design_id>/`。

意涵，为避免不同 design 的 IO 布局规则混杂，固定规则如下：clock 端口统一约束到 top；reset 端口统一约束到 bottom；普通 input 统一到 left；output 统一到 right；inout 统一到 bottom；每组端口按字典序并以 `-group -order` 放置。所有 design 使用 `CORE_ASPECT_RATIO=1.0`、`CORE_UTILIZATION=45`、`CORE_MARGIN=10`、`PLACE_DENSITY=0.30`、`GPL_RANDOM_SEED=1`、关闭 timing-driven placement，并固定 `metal5/metal6` IO layer 和 corner/min-distance 约束。这样统一的是 IO 角色、芯片外形、密度、随机种子和 pin placer 参数；内部标准单元位置仍由各自网表决定，不能声称不同电路拥有完全相同的内部布线。

意涵，脚本只运行 `do-1_synth`、floorplan、tapcell、placement 和 `do-3_place`，明确不运行 CTS、global route、detailed route、OpenRCX、STA 或 power。每个 design 记录 `placement_manifest.json`，包括固定规则版本、IO 分组计数、placer 参数、返回码和 `3_place.*` 产物。当前队列会话为 `fixed_io_place`，日志为 `/data/yiyh/dac2027/dataset/circuit/circuitnet3_nangate45_fixed_io_placement_v1/queue.log`。

意涵，启动命令如下；`--design-list` 只选择 1500 子集，`--workers 2 --threads 16` 是资源上限，不能改成多 worker 共享同一 ORFS work 目录：

```bash
tmux attach -t fixed_io_place
/data/yiyh/dac2027/envs/v2ex_cuda/bin/python3 script/run_circuitnet3_fixed_io_placement.py \
  --design-list /data/yiyh/dac2027/dataset/circuit/circuitnet3_subset1500_v1/manifest.json \
  --output /data/yiyh/dac2027/dataset/circuit/circuitnet3_nangate45_fixed_io_placement_v1 \
  --workers 2 --threads 16 --timeout 1800
```

意涵，验收必须同时检查：`manifest.json` 的 requested 数量与 1500 白名单一致；每个成功 design 有 `3_place.odb`；`placement_manifest.json` 的 `fixed_io_version` 为 `fixed_io_v1`；抽检 `3_place.odb` 导出的端口坐标时，clock/reset/input/output/inout 分别落在 top/bottom/left/right/bottom 区域。队列完成后，再单独运行 map-place pair builder 写入 `circuitnet3_map_place_pairs_fixed_io_v1`，不会回写旧 pair。

## 并行边界

意涵，当前机器为 128 个逻辑 CPU、约 503 GiB 内存；本轮 OpenROAD 使用 `3 x 32` design 级并行并已完成，map-place、route/RC 和 task registry 由 supervisor 串联提交，最终 manifest 已写入。每个阶段仍必须由主进程统一写 manifest，禁止多个 supervisor 同时覆盖同一输出目录。

map-place 和 route/RC builder 会复用已有完整 design 目录，只处理新增或不完整 design；因此每轮 supervisor 是增量流水线，不会重复重建已经提交的 pair。

意涵，当前构造已完成，本项目的 `dac2027-phys` 和 `dac2027-pipeline` tmux 会话已清理；其他项目会话未触碰，最终状态以四个 manifest 和 pipeline latest 快照为准。

## S1 概率/状态漏电轨道

意涵，S1 新增脚本为 `script/build_s1_probability_labels.py`、`script/build_s1_probability_pairs.py` 和 `script/package_s1_probability_tensors.py`。前者解析 Nangate45 Liberty 的 `leakage_power(when,value)` 状态表，在 mapped netlist 上传播 primary input 概率并生成状态加权漏电；后两者登记图对并把四个字段写入宽张量与 CC-Tensor v3。

意涵，独立 S1 数据目录为 `circuitnet3_s1_probability_labels_1500_v1`、`circuitnet3_s1_probability_pairs_1500_v1`、`circuitnet3_v3_03_task_tensors_s1_probability_1500_4096_v1` 和 `circuitnet3_v3_03_compact_tensors_s1_probability_1500_4096_v1`，不覆盖原 S1 张量。`signal_prob` 和 `leakage_power` 是监督字段，不是模型输入特征；模型适配属于后续实验职责。

意涵，V3.04 OpenROAD S1 修复轨道使用 `script/export_opensta_s1_probability.tcl` 和 `script/build_opensta_s1_probability_labels.py`。导出器读取 Nangate45 tech/cell LEF、Liberty 和 mapped Verilog，在无 SDC 的综合网表上建立 1 ns 虚拟 activity 时钟，使用 OpenROAD activity engine 传播 pin duty，并将 duty 作为 `signal_probability`；实例 `report_power -instances -format json` 的 leakage 回填为 `leakage_power_target`。该轨道与旧纯 Python S1 完全分目录隔离。

意涵，V3.04 不能表述为“OpenSTA 直接给出 BDD 精确概率”：本机工具契约公开的是 activity/duty，当前标签来源为 `OpenROAD activity duty`，metadata 明确记录 `correlation_model`，后续必须用重汇聚反例和引擎输出做经验审计。OpenROAD 输出 pin 名为 `cell/pin`，图节点为 `cell.pin`，调度器在末级做确定性名称归一化。
