## V3.02 纯净动力学主线（2026-10-29）

- 独立测试包位于 `test/v3_02/`，正式生产包位于 `code/v3_02/`，正式训练脚本为 `script/train_v3_02_hops.py`，单测脚本为 `test/test_v3_02_smoke.py`。
- 架构特性：
  - `interactions.py`：`PairOperations` 显式解耦并引入独立源节点状态 $s_j$ 与目标节点状态 $s_i$，基底扩展为 $[s_j, s_i, s_j - s_i, s_j \odot s_i, W_{\text{src}} s_j - W_{\text{dst}} s_i, \|s_j - s_i\|_2]$，总通道数 $5d_s + 1$；
  - `interactions.py`：`aggregate` 彻底移除除以有效节点数 $N_{\text{valid}}$ 的归一化操作，采用纯粹 `sum` 累加，消除图规模对跳数尺度的稀释；
  - `model.py`：彻底移除固定外生步长 $\eta=0.05$，演化状态还原为纯净势能累加 $s_{t+1} = s_t + \text{field} + \text{noise}$；
  - `readout.py`：`IntrinsicReadout` 同步使用该扩展基底，实现 `offre` 与 `rout` 的严格对称（`offre` 仅多先验关系 $re_{ji}$ 输入）。
- 代码规范：所有 Python 文件严格控制在 150 行以内，配备详细中文注释，强制 CUDA 支持。
- 实验记录：8 层 1000 步训练正跳数 MAPE 达到 `13.07%`，全可达 MAE 为 `0.2360`，舍入准确率 `88.83%`，结果位于 `/tmp/v3_02_hops_t8_pure/`。

## DAC-EDA 任务清单

这里的 DAC-EDA 任务专指 `/home/yiyh/graphmath/dac2027` 的 mapped-circuit-v2、pin-timing-arc-v1
和 Agent Phase 2 协议，不包含上表中的合成、分子、Cora 任务。当前主线是新算法的 DAC predictor；
Agent Phase 2 只作为 predictor 之上的子实验。

### E-DAC 数据集预测任务

1. **Mapped-cell power：** 预测每个 standard cell 的 `internal`、`switching`、`leakage` 和 `total` power。
2. **Graph total power：** 对 mapped-cell power 预测做物理节点求和，预测整图 total power。
3. **Mapped-cell area：** 预测每个 mapped standard cell 的 Liberty area。
4. **Graph area：** 对 mapped-cell area 预测做节点求和，得到整图 area。
5. **Pin cell-arc worst delay：** 预测 `CELL_ARC` 的 worst propagation delay。
6. **Pin cell-arc rise delay：** 预测 `CELL_ARC` 的 rise propagation delay。
7. **Pin cell-arc fall delay：** 预测 `CELL_ARC` 的 fall propagation delay。

其中 `NET_ARC` 目前只作为 timing graph 拓扑，不提供 delay target；节点/边结构恢复、AUC/F1
和 recovery loss 是辅助表示证据，不替代上述八个独立 predictor 任务。graph area/total power
是节点结果的物理聚合评估，不新增训练任务。

### 下一版 DAC 数据集需求

1. **Mapped power 输入：** 每个 standard cell、net bit 或 pin 提供可追溯的 activity/toggle rate、时钟/仿真频率、
   input transition/slew、输出 load 或等价 capacitance、逻辑状态/向量条件，并记录单位、来源和有效性 mask。
2. **Timing 输入：** 每条有向 `CELL_ARC` 提供 source pin、target pin、arc type、rise/fall 条件、input slew、output load/
   capacitance，以及与 delay label 相同 corner、library、voltage、temperature 的 metadata。
3. **关系对齐：** 所有边级字段必须与 `edge_index` 的有序端点逐条对齐；缺失字段使用 edge mask，不能广播节点均值代替。
4. **节点对齐：** pin-level 字段必须对应 `cell_pin/primary_input/primary_output/primary_inout` 节点；不能把 mapped-v2
   的 cell/net 标签直接复制到 pin timing 图。
5. **标签与输入条件一致：** power/delay 标签必须保留 tool、corner、activity source、frequency 和运行状态；不同条件不能
   混入同一个监督通道而不提供 condition ID。
6. **可复现 split：** 按 design/source 去重后固定 train/valid/test，并在 manifest 中记录字段覆盖率、零值数量和每类有效样本数。

### Agent Phase 2 真实 EDA 优化任务

1. **T1 timing closure：** 在保持功能等价的条件下修复 worst delay 违例。
2. **T2 area compression：** 在满足时序约束的条件下最小化 mapped area。
3. **T3 power compression：** 在满足时序约束的条件下最小化 total power。
4. **T4 multi-objective PPA：** 同时满足 power、area、timing 预算并优化综合 PPA score。

T1–T4 是受控 RTL/ABC 优化与真实 EDA 验收子实验，不等同于 E-DAC 的节点/边回归主任务；
快速 `S` 工具只能提供预测，最终结果必须由真实 Yosys/ABC/OpenSTA 和等价检查确认。

## V1-C 自包含候选

`code/v1_c/` 完整包含 V1 所需的 ENCS、ENCR、SETATTN、PAIRATTN、ENCO、Gate、EvolutionLayer、Decoder、AdaptiveNoiseFilter、loss、training 和 downstream 模块。V1-C 只使用包内相对导入，不依赖 `code/v0/` 或 `code/v1/`；入口类为 `v1_c.V1CModel`。`test/test_v1_c_isolation.py` 已通过 CPU smoke，验证本地导入、完整前向、padding 输出、张量形状和反向传播；尚未完成 CUDA、真实数据训练或 test 评估，因此不替换当前 V1 主线。

## V2 隔离基线

`code/v2/` 是 V2 的独立代码包，完整复制 V1-C 的核心算子、任务头和训练工具；入口类为 `v2.V2Model`。
当前 V2 保留 V1-C 核心 ENCS、ENCR、SETATTN、PAIRATTN、ENCO、Gate 和 EvolutionLayer，并在独立包内增加
dense multi-hop relation head 与 Electricity Meter 候选。V2 源码使用包内相对导入，不能依赖
`code/v1_c/`、`code/v1/` 或 `code/v0/`；`test/test_v2_isolation.py` 已通过 CPU 前向/反向 smoke、padding mask
和静态依赖审计。后续 V2 结构变更必须在该包内独立测试，不修改 V1-C 实现。

### V2 Dense Multi-Hop 实验

稠密多跳任务的读出不是 Electricity Meter，而是 `PAIRATTN` 生成节点对表示，`ENCR` 独立编码有向关系向量，
两者在 relation head 中融合，预测全 pair `reachable` 和可达 pair `min_hop`。`PAIRATTN(i,j)` 只读取有序节点对；
关系向量不直接送入 `PAIRATTN`。

### V2 Electricity Meter 实验

`code/v2/electricity_meter.py` 将原生 timing 图的节点/关系 one-hot 类型转换为单整数 ID，并由 V2 内部
embedding 映射到高维；其它原生节点属性保留为连续输入。每个有效 Launch-Capture query 追加一个 meter
节点，加入有向 `measure` 边 `source -> meter -> target`，以及 meter 与其它有效节点之间的双向
`measureunlink` 边。V2 使用 SETATTN 读出所有 meter embedding，每个 meter 预测一个 `path_delay`。
`test/test_v2_electricity_meter.py` 已通过 CPU 图构造、关系方向、SETATTN 读出和反向 smoke；真实 DAC
virtual timing 训练和 CUDA smoke 尚未完成。
